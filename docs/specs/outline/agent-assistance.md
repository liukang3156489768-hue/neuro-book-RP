# 大纲规划模块 Agent 协助

## 目标与非目标

本能力提供常驻规划 Agent，协助用户生成、检查、关联和维护大纲库、伏笔库、线路规划及其标记。本能力不允许 Agent 写正文、新建角色/物品/地点或修改素材基础资料；仅允许随规划保存维护已有对象的方案改编记录，见 [outline.material-adaptation](material-adaptation.md)。不把模型输出自动当作事实，也不绕过删除审核。

## 术语与参与者

用户拥有最终确认权。模块 Agent 可读取当前项目 `lorebook/`，读写规划模块；正文写作模块是下游只读消费者（见 [outline.writer-handoff](writer-handoff.md)）。

模块 Agent 下设三个专用子 Agent，它们是最终条目的产出者，可读写规划模块，并通过规划动作同步维护受限的方案改编记录：

| 子 Agent | 负责的问题 |
|---|---|
| `outline`（大纲） | 总纲、卷纲、章节大纲的骨架与方案组织，以及已有伏笔的埋设、强化和回收安排 |
| `Detailed outline`（细纲） | 细纲、写作指导、参考文件和篇幅 |
| `foreshadowing`（伏笔） | 伏笔设计，以及依据派生状态给出埋设和回收建议 |讨论模式要求用户审阅操作；自动模式按持续授权执行非删除操作。建议是未生效内容，正式变更是已确认并写入规划的操作。

## 输入与前置条件

创作方式是会话初始合同：新建会话时选择 `original` 或 `adaptation`，首条用户消息产生后锁定；切换历史会话恢复其合同，只有新建会话才能重新选择。两种方式使用独立的 Profile 行为分支，后续任务消息只能携带目标方案，不能覆盖会话方式。原创方式先检查 lorebook 类别存在性再按用户构思按需读取；改编方式先选择带 `source-extraction` 依据的来源方案，再检查所需类别。改编起点由领域入口一次创建新方案、总纲、第一卷和第一章。

Agent 会话必须绑定当前项目和规划范围，并明确当前模式、模型、思考开关和温度设置。两种模式都以用户当前指令为操作范围，超出范围的改动需先说明，再按当前模式另行确认。上下文按需读取 `lorebook/`、正式规划和用户当前选择，不无条件注入全部正文；大纲规划操作合同与各级大纲正文模板随 Profile 直接载入模块主 Agent 和三个子 Agent 的上下文，它们位于安装资产目录，不在 Project 内，Agent 不按路径读取；正式规划的线路部分以紧凑的线路图摘要呈现（节点格号、行号、条目标题，连线，线路及其节点），线路写操作只能使用线路图领域操作（图节点与连线的增删改、插入列、线路创建与编辑、重开、切换主线）。写操作必须生成目标、变更、影响范围和可撤销信息。对象删除是删除规范文件，关系删除是移除引用或关联关系；两者都必须展示级联影响预览并进入审核，自动模式也不能绕过。总纲删除需要二次确认；被其它方案挂载或被线路节点关联的对象可以删除，但预览必须列出这些引用与受影响节点，审核通过后才会级联删除并清理挂载。

## 子 Agent 委派

- 只有模块主 Agent 能委派，且只能委派这三个子 Agent；子 Agent 不能再委派，模块主 Agent 也不获得通用的创建 Agent 能力。
- 子 Agent 会话挂在主会话之下，绑定同一 Project；同一主会话内同类子 Agent 复用同一会话。
- 委派分两种：
  - **咨询**：子 Agent 只读取和预览；主 Agent 核对提案后，按讨论／自动模式处理；
  - **委派产出**：讨论模式下，用户先确认委派范围，自动模式直接执行。子 Agent 在范围内写入规划条目；关联素材的新信息随规划动作的 `materialUpdates` 同步提交。
- 写入授权只在一次经放行的委派调用期间存在，由服务端校验；咨询或普通会话中调用写工具一律拒绝。
- 子 Agent 的规划写入必须带有效预览的 proposalId，经规划领域服务校验；只允许条目与伏笔的新增、编辑和确认。删除、解除关系和线路操作拒绝，交回主 Agent 审核。
- 主 Agent 和专家使用受控的分页素材列表与读取工具，不持有通用文件读取或 `write_lorebook`/`edit_lorebook`。改编写入仅指向真实已有对象的当前方案专用目录，由规划领域统一校验、提交和撤销；基础文件、提取经历及关系不可写。
- 每次委派传递最新创作方式、目标方案、已明确的稳定来源锚点与所选素材路径，并在 brief 中说明任务范围和保留/变化约束。复用子会话不得沿用旧任务的方案或授权；缺少上下文时按本次 brief 核实，含糊项返回待澄清问题。
- 子 Agent 不能撤销、不能调用其他 Agent，也不直接向用户提问。
- 子 Agent 返回结构化报告：摘要、带依据类型（事实／推断／建议）的提案、已写入对象及事务 id、待澄清问题。
- 主 Agent 向用户逐项汇报写入结果；子 Agent 返回错误或进入等待时，主 Agent 如实告知用户，不把结果当作成功。

## 输出与可观察行为

Agent 可流式输出分析、生成草案、冲突报告、伏笔建议和操作预览。待审阅列表展示建议、来源、影响、风险和确认控件。用户可逐项或批量确认、拒绝、修改后重试或撤销已执行变更。自动模式执行的非删除变更仍产生同等审计记录。

### 上下文压缩

规划会话沿用 Agent 运行时的上下文压缩设置。默认在估算上下文达到约 500,000 tokens 时执行维护；缓存读取和缓存写入也计入单次上下文，不能只按未缓存输入判断。模型窗口小于此触发线时，按窗口减输出预留提前触发。用户或 Profile 显式配置的触发方式与启停设置优先于默认值。完整请求估算包含系统提示、工具定义、动态资料及历史，Provider 校准值不重复叠加同一固定前缀；此值是估算而非提供方精确分词。

检查在每次新指令的首轮模型请求之前，以及同一次任务继续调用模型之前执行。默认保留约 24,000 tokens 的近期历史，并补入历史摘要与当前规划合同；本轮附加条目、当前用户输入及完整工具调用组不得因近期预算被截断。较旧的巨型读取进入摘要，不能为了凑满近期预算整条保留。提示词顺序仍为历史与合同、实时模型上下文、本轮附加条目、当前用户输入。

500k 是维护触发线，不是每次请求的精确上限；近期保留以完整消息和工具组为边界。超过触发线时先消除旧规划工具结果中的相同资料，重新计量后仍越线才摘要。原日志不删除，替换仅作用于当前分支且要求源指纹与完整参考结果仍有效；当前输入、编辑正文、CAS 字段和用户决定不做头尾截断。普通追加轮不反复改写历史前缀。

规划读取默认返回紧凑概览；完整条目索引、方案挂载与图拓扑按需分页。指定条目详情只返回目标完整正文、版本、哈希及必要关联，不附带全项目集合。分页支持版本前提，版本漂移时重新读取，不能把不完整概览用于替代完整编辑内容。

摘要请求保留原系统提示、工具定义及可见历史消息角色，摘要指令追加在末尾；旧摘要合并仍有效的用户决定、创作约束、稳定引用和待办，去掉过期事实。能在模型安全预算内完成时只摘要一次，超长历史按完整工具组分批；巨型工具组以明确标注的数据片段完整交付摘要，全部成功后才保存一份最终摘要。后续请求使用摘要与近期消息，不再把压缩前的 Provider 用量当成当前上下文估算。摘要失败、取消、空输出、工具调用或输出截断均不保存部分摘要，不继续发送原巨量主请求。

压缩期间聊天显示实际整理／摘要阶段、旋转指示、真实批次数量及耗时；完成后显示压缩前后估算上下文、独立摘要用量、缓存命中率与费用。主请求累计统计与摘要费用分别展示。停止操作透传到摘要请求；重连从当前活动 invocation 恢复，旧运行记录不得产生永久动画。缓存复用属于请求结构优化目标，不能保证特定 Provider 的实际命中率。

## 状态与转换

| 事件 | 结果 | 备注 |
|---|---|---|
| Agent 生成内容 | 待审阅建议/草稿 | 不自动成为正式内容 |
| 讨论模式用户确认 | 执行正式变更 | 需校验和记录 |
| 自动模式获授权操作 | 执行非删除变更 | 删除仍需审核 |
| 批量确认 | 一次提交明确展示的变更 | 任一失败需报告部分结果 |
| 撤销 | 恢复变更前版本/关系 | 不覆盖用户之后的新变更 |
| 用户取消或会话中断 | 不提交未完成操作 | 流式输出可保留为会话记录 |

## 副作用与数据

会话、模型设置、建议、审批、操作预览、正式变更、撤销和错误必须进入项目可审计历史。文件写入必须经规划模块公开操作边界；对象删除实际删除规范文件，关系删除只删除引用或关联关系；事件流用于 UI 流式展示，不得绕过领域校验。Agent 不拥有正文或通用 `lorebook/` 写入权限；方案改编记录属于规划提交的受限关联产物。

上下文压缩追加摘要记录，保留原始聊天记录、工具结果与累计用量和费用，不物理删除历史。后续回复必须延续包含摘要的有效历史分支，使压缩结果在下一次指令中继续生效。

## 失败与恢复

模型超时、流式中断、权限不足、校验失败、版本冲突或部分批量失败时，未提交操作保持草稿并明确显示；已提交部分可单独撤销。迟到完成不能覆盖用户新版本。撤销目标已发生冲突时转为预览/人工处理，不强制覆盖。

自动摘要失败、为空、被输出上限截断或取消时，不保存部分摘要，不发送未经压缩的原巨大上下文；已接收的本轮输入仍保留。摘要成功后，若必须保留的当前输入或完整工具组仍超过模型窗口，则明确提示缩小输入或附加资料，阻止主请求，不静默截断用户内容。

## 边界与兼容

权限必须由服务端/领域边界强制，而不是依赖 UI 隐藏按钮。自动模式不追溯修改历史授权；切换模式只影响后续操作。与既有 Agent Session、事件流和历史机制复用时不得改变其他 Agent 的权限合同。

## 验收与 Smoke

- Given 讨论模式建议新增伏笔，When 用户拒绝，Then 不产生正式伏笔或标记。
- Given 自动模式批量修改三个规划条目，Then 一次确认后执行，三项各有审计记录并可撤销。
- Given Agent 请求删除总纲，Then 显示引用/级联预览并要求二次确认。
- Given 任一规划 Agent 尝试写正文、新建素材对象或修改已有基础资料，Then 服务端拒绝并记录权限错误。
- Given 流式响应中断，Then 已显示内容保留为会话记录，未完成变更不提交。
- Given 主 Agent 就细纲问题咨询 `Detailed outline`，Then 子 Agent 只返回报告和预览，规划文件不变，直到主 Agent 按模式执行。
- Given 讨论模式下主 Agent 委派 `Detailed outline` 产出细纲，Then 用户先确认委派；确认后子 Agent 写入细纲及关联方案改编记录，并返回事务 id。
- Given 委派期间子 Agent 尝试删除对象、操作线路或直接写素材文件，Then 服务端拒绝。
- Given 子 Agent 或其他 Profile 尝试委派，Then 服务端拒绝。
- Given 百万窗口模型的旧会话包含约 868k 缓存上下文，When 用户发送新指令，Then 首轮规划请求之前先生成摘要，并保留规划合同、本轮附加条目和当前输入的顺序。
- Given 压缩后的近期消息仍带原来的 Provider 用量，When 下一次指令启动，Then 当前上下文估算不继承压缩前的巨大缓存计数，原始历史与累计费用保持可审查。
- Given 长历史需要多批摘要，When 任一批失败、取消或达到输出上限，Then 不保存部分摘要，也不发送原巨大上下文。
- Given 连续工具调用触发摘要，When 后续回复持久化并再次发起指令，Then 有效历史分支仍包含摘要，不恢复压缩前历史。

## 实现合同

已实现规划 Agent 的工具白名单、Project 作用域 Session、预览／审批／撤销、删除二次确认、审计记录、事件流、取消和过期版本门禁。工具只通过规划领域入口读写，建议不写盘，审批拒绝或取消不会提交；工作台通过现有 Session/SSE 合同消费流式输出和待处理审批。faux Agent Session 黑盒、规划工具合同及工作台合同已有回归；Profile 运行时 fixture、完整浏览器、默认全包和真实模型仍未验收，因此本 Spec 维持 `planned`。

三个专用子 Agent 及本轮素材权限收窄：
- 规划助手有 `consult_planning_specialist`（咨询）和 `delegate_planning_task`（委派产出）两个工具，委派工具声明写入，讨论模式下由 harness 先请用户审批；
- 主 Agent 和子 Agent 有 `list_planning_materials`、`read_planning_material`，不持有通用素材读写工具；
- 子 Agent 的 `commit_planning_change` 受委派期门禁约束，关联改编内容经条目动作的 `materialUpdates` 保存；
- 素材运用与改编指南直接载入四个 Profile，角色基础/经历/关系按任务读取，写作手法与素材先读索引再选正文；每次委派携带最新任务上下文。

工具门禁、真实 Project 下的 `lorebook/` 路径校验与 Profile 静态合同已有回归；真实模型端到端委派尚未执行。
