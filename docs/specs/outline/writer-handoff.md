# 正文写作规划交接

## 目标与非目标

本能力是大纲规划模块向正文写作模块（写作工作流与助手，见 [writing.collaboration](../writing/collaboration.md)）开放的只读接口。写作模块通过它得到：

- 写作方案中各章节的目录与可写资格；
- 可写章节的正式上下文。

章节的范围、所属的卷和先后顺序都以大纲库中该方案的层级为准。线路规划暂时只供用户梳理剧情，本能力不读取线路、节点、格号或线路的固定状态，也不用它们判断资格或排序。

本能力不提供规划写入、伏笔状态修改或正文回写。

## 术语与参与者

- **写作方案**：大纲库中的一条方案链；其上游总纲是该方案自己的总纲（每方案一个，见 [outline.planning-library](planning-library.md)），不是全局总纲。
- **章节目录**：写作方案中全部章节大纲，按层级顺序排列：先按方案中卷纲的顺序，卷内再按章节大纲的顺序；不属于任何卷纲的章节排在最后。
- **本章细纲**：写作方案中挂在该章节大纲下的细纲，按方案中的顺序排列。
- **可写**：章节大纲已正式采用，且本章至少有一份细纲、每份细纲都是已审阅的正式细纲。“已审阅”包含两种依据：通过分析审阅，或采用依据为“来源提取”（见 [outline.planning-library](planning-library.md) 的“细纲的采用依据”）；两者在资格上等价。
- **正式上下文**：可写章节的章节大纲、本章细纲、写作指导、素材索引、参考文件和伏笔标记处原文。

## 输入与前置条件

- Project 已打开，写作方案 id 有效。
- 读取章节目录时，请求携带写作方案 id。
- 读取章节上下文时，请求携带写作方案 id 和章节大纲 id，可以附带调用方上次读到的版本，用于检测变化。
- 查询服务按大纲库的当前状态校验条目正式状态、细纲审阅状态和引用有效性。任一条件不满足，就不返回正式上下文，也不降级读取草稿。

## 输出与可观察行为

### 章节目录

每个章节返回：

- 章节大纲的稳定 id、标题、版本、内容哈希、所属卷纲的 id 与标题；
- 本章细纲的 id、版本、内容哈希；
- 是否可写；不可写时给出原因：大纲未采用、细纲未审阅（包括没有细纲）。

### 章节上下文

对可写章节返回：

- 章节大纲正文及其写作指导、目标字数、参考文件清单；
- 按方案顺序排列的本章细纲，每份包括正文与素材索引；细纲的字数、人称、写作指导与参考资料都在正文模板里（见 [outline-entry-templates.md](./outline-entry-templates.md) 的「细纲」），参考文件清单由正文各场景的「参考资料」派生，没有链接的项作为待补告警返回；
- 章节大纲中的伏笔标记：
  - 包括标记处原文、动作（埋设、强化、回收）、伏笔稳定 id 与版本；
  - 只返回已确认伏笔的标记；
  - 不交接伏笔定义正文，因为其中的背后关联和回收计划会让正文提前泄露后续剧情，需要呈现的内容由细纲和写作指导落实；
  - 不按线路判断伏笔先后；
- 标为“待补”的参考文件，作为告警返回；
- 每项内容都带稳定 id、版本和来源位置。

另有素材读取：按正式条目的参考清单读取素材内容，并返回来源审计。待补参考文件不可读取。

对不可写章节，本查询拒绝返回上下文，并给出与章节目录相同的原因。

## 状态与转换

本能力不引入新的规划状态，只读取大纲库的当前状态：

- 章节大纲回到草稿，或本章细纲变为草稿、被删除时，读取资格立即撤销，直到重新采用或审阅。
- 调用方附带的版本与当前版本不一致时，返回当前版本和变化标记，由调用方处理，不静默替换正在进行的写作任务的依据。

## 副作用与数据

- 只读查询不写规划，可以记录访问审计和上下文版本。
- 写作模块无权写入规划文件、线路、伏笔或 `lorebook/`。
- 缓存按项目、写作方案和条目版本隔离；失效时不能拿旧结果冒充当前结果。

## 失败与恢复

项目关闭、写作方案不存在、版本冲突、条目或细纲损坏、权限不足时都 fail-closed，返回可解释的错误和需要用户处理的原因。恢复后重新查询；不自动修复规划，也不改写正文。

## 边界与兼容

- 本交接的唯一消费方是正文写作模块（[Proposal](../../proposals/writing-module.md)），它取代《新小说编写计划》原设计中的 `writer.pro`。现有 `writer` Profile 不接入本交接。
- 本能力是规划模块到正文模块的单向只读边界，与现有 Plot 和 Writer Brief 互补，不替换 Plot。规划模块只交接稳定 id、版本和正式上下文，不复制 Plot 的 Story、Thread、Scene、Promise、Decision、World Engine 关联或 Writer Brief，不建立第二套 Scene 真相源。
- 任何写入请求都由服务端拒绝。
- 线路规划的节点状态（红、黄、重复、未固定）不影响本交接的结果。

## 验收与 Smoke

- Given 写作方案中两个卷各有两章，When 读取章节目录，Then 按卷纲顺序、卷内章节顺序返回四章，并各自标出是否可写。
- Given 章节大纲已采用、细纲已审阅，但没有关联任何线路节点，When 读取章节上下文，Then 返回正式上下文。
- Given 章节大纲为草稿，或细纲未审阅，When 读取，Then 不返回上下文并说明原因。
- Given 已关联的线路节点被标红或标黄，Then 章节的可写资格和上下文不受影响。
- Given 章节大纲中有伏笔标记，Then 返回标记处原文和动作，不含伏笔定义正文。
- Given 本章有两份已审阅细纲，Then 按方案中的顺序返回。
- Given 写作模块发出写请求，Then 服务端拒绝，规划文件保持不变。
- Given 两个方案各有不同的总纲，When 分别读取两个方案的章节上下文，Then 各自返回自己方案的总纲内容，互不混入。
- Given 提取方案中章节大纲已采用、细纲采用依据为来源提取，When 读取章节目录与上下文，Then 该章可写并返回细纲；When 用户编辑该细纲正文，Then 该章变为细纲未审阅。

## 实现合同

ready Project 提供两个只读接口，实现位于 `packages/neuro-book/server/outline/writer-context.ts`、`writer-materials.ts` 与 `host.ts`：

- `read-writer-chapters`：请求体只含 `planId`，返回 manifest revision 和章节目录。每章带 `writable`；不可写时 `block.code` 为 `OUTLINE_NOT_ADOPTED` 或 `DETAIL_NOT_REVIEWED`，`block.message` 说明具体原因。
- `read-writer-chapter-context`：请求体含 `planId`、`chapterEntryId`，可选 `expectedBasis` 与 `materialPaths`（1 到 8 个不重复路径）。
  - `basis` 由章节大纲与本章各细纲的版本和内容哈希组成。附带 `expectedBasis` 时返回 `basisChanged`；不附带时不返回该字段。
  - 章节不可写时返回 422，原因与章节目录一致。
  - 细纲审阅复用 `assertDetailReviewed`：审阅报告、来源哈希或审阅上下文不匹配时视为未审阅。审阅上下文只覆盖细纲的上游链（见 [outline.planning-library](planning-library.md)），同章多份细纲可以同时可写。
  - 伏笔标记直接取自章节大纲的 marker，按原文位置排序，只保留定义已确认的标记，不做线路先后判定。
  - 素材只能来自本章章节大纲或细纲的 `materialRefs`，来源记录条目 id、版本、内容哈希、路径和字段。素材读取前后规划依据变化时返回 `CAS_CONFLICT`。

消费方正文写作模块已实现（见 [`writing/`](../writing/) 下各份 Spec，状态待开发者确认后提升），2026-09-30 在示例项目中经真实模型写作验收：写作按交接的章节目录与正式上下文进行，不读取线路。此前曾把现有 `writer` Profile、通用文件工具、章级写作评审 workflow 和写作 smoke 改造成本交接的消费者，2026-09-26 已全部回退。

本能力维持 `planned`。
