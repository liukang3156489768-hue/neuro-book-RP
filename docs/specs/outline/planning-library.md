# 大纲库与细纲

## 目标与非目标

本能力为作品提供可复用的灵感与方案库，管理总纲、卷纲、章节大纲及其细纲。大纲库不承担严格时间顺序；正文使用顺序由线路规划决定。本能力不生成正文，不把草稿直接交给 `writer.pro`，也不替用户决定唯一方案。

## 术语与参与者

- 总纲：作品全局纲领，规划范围内只能有一个。
- 方案链：同一作品的一个完整展开方案，可存在多条；所有方案链共同引用唯一全局总纲，并各自组织卷纲、章节大纲。
- 章节大纲：可被线路节点引用的剧情规划单元，与正文一对一。
- 细纲：依托章节大纲的场景细化，可有一个或多个连贯片段。
- 用户：可编辑、确认、删除和处理冲突的人类操作者。
- 模块 Agent：可按授权生成建议和执行规划操作，但不写正文或 `lorebook/`。

## 规范文件与领域边界

结构化项目文件是本能力的规范来源，SQLite 只保存可重建索引、查询加速数据和解析摘要。大纲、卷纲、章节大纲和细纲保存于 `outline/entries/<slug>--<stable-id>.md`，使用 YAML front matter 保存结构化字段、Markdown 正文保存叙述内容；模块版本和顶层索引保存于 `outline/manifest.yaml`。稳定 ID 不因移动、重排、改名或关系变化而改变。

对象删除与关系删除分开：对象删除是删除规范文件，关系删除只移除父子、引用、节点关联或线路成员关系。被其它方案挂载或被线路节点关联不阻止对象删除：容器条目级联删除全部子孙条目，所有方案中指向被删条目的挂载关系一并清理，关联的线路节点保留并标记失效，由用户后续修复。删除前必须预览并展示外部引用、受影响线路节点和级联条目数，经用户确认并记录历史后提交。

本能力拥有大纲库和细纲规划语义，不拥有正文、`lorebook/` 或线路最终顺序；与现有 Plot 互补，不替换或复制 Plot 的 Story、Thread、Scene、Promise、Decision、World Engine 关联和 Writer Brief。

## 输入与前置条件

用户可手动新建条目，或提供简单方向请求生成草案。创建和编辑必须带项目身份、稳定 ID、父级关系和当前版本。跨方案复用通过引用同一条目实现。修改共享条目前必须提示影响范围并由用户确认写时分叉；分叉产生新文件、新稳定 ID 和不同名称，不覆盖源文件且不重新合并。目标方案的线路若仍引用源条目，须先处理线路节点；分叉不得留下悬空引用，也不得默默将固定线路改绑到新草稿。

细纲正式保存前必须完成 AI 偏差/冲突分析并允许用户选择保存为草稿或正式文本。章节大纲可没有细纲，但细纲不得脱离章节大纲正式存在。

## 内容要素

- 卷纲与章节大纲写明起点、主要发展、关键事件、转折和阶段落点。
- 细纲正文覆盖：本章承接的局面、主要内容和结束位置；场景顺序、人物行动、事件发展和场景衔接；必须呈现的细节、对白意图、信息披露和已有伏笔安排。细纲完成必要的剧情决定，但不逐句指定正文措辞。以上作为生成草案和偏差分析的检查清单，不强制拆成结构化字段。
- 写作指导按场景或片段锚定，推荐说明展开或略写、手法和重点。
- 参考文件标注写明资料、所用部分和用途；没有实际可查阅来源时标记为“待补”，不得编造路径或内容。“待补”不阻止正式采用，但要在偏差分析结果和正文交接中作为告警出现。
- 篇幅支持章节总目标字数，必要时按场景分配大致字数。

## 输出与可观察行为

界面以阶梯式层级显示唯一全局总纲下的多条方案链，支持新增、删除、移动、重排和展开条目。章节大纲显示正文、伏笔使用/回收标记和素材索引，并可在同一详情中查看其细纲及标注；细纲显示素材索引、写作指导、参考文件和篇幅要求。草稿、正式采用、埋设伏笔、回收伏笔作为条目标记展示；正式采用的章节大纲只有在线路中固定后才进入正文写作上下文。

生成结果先显示为可审阅草案。正式保存时显示分析结果、偏差和冲突；失败时保留草稿并阻止正式采用。

## 状态与转换

| 事件 | 结果 | 拒绝条件 |
|---|---|---|
| 新建/生成 | 草稿条目 | 项目身份或父级无效 |
| 用户确认正式采用 | 正式条目 | 必需分析失败或存在未处理冲突 |
| 共享引用位置修改并确认 | 新分叉条目 | 用户取消则原引用不变 |
| 删除条目 | 删除关系或对象，分别处理；对象删除级联子孙并清理全部挂载 | 预览未确认；总纲未二次确认 |
| 细纲保存 | 草稿或正式 | 正式保存未完成分析 |

移动和重排不改变稳定 ID。全局总纲删除需要二级确认；方案链关系不能复制出第二个总纲对象。删除级联影响必须先展示预览。

## 副作用与数据

条目、引用、版本、草稿/正式状态、素材索引、细纲和分析结果必须按项目持久化并进入可追溯历史。结构化项目文件是唯一规范来源，SQLite 只作为可重建索引、查询加速数据和解析摘要；不得双写为两个独立真相源。每次正式变更应能够从文件重建层级和引用关系，索引损坏不得反向覆盖规范文件。

## 失败与恢复

父级不存在、引用失效、版本冲突、分析超时或文件损坏时拒绝正式提交，保留用户原文和草稿。用户取消分叉、删除或级联操作时不改变源条目。重开项目后从规范来源恢复；索引损坏时可重建，不以空索引覆盖文件。

## 边界与兼容

本能力拥有大纲库和细纲的规划语义，不拥有正文、`lorebook/` 或线路最终顺序。本能力不提供从旧笔记或设计文档导入规划的功能。任何正文 Agent 只读正式线路交接结果。

## 验收与 Smoke

- Given 新项目，When 创建两个方案并共享一个条目，Then 两个方案共同引用同一个全局总纲，两个位置引用同一条目稳定 ID，且共享条目修改确认后只在当前位置产生新 ID。
- Given 章节大纲保存细纲，When 选择草稿，Then 不触发正式使用；When 选择正式，Then 必须展示分析结果并在冲突未处理时拒绝。
- Given 被其它方案挂载或被线路节点关联的条目，When 请求删除，Then 先显示引用、受影响节点和级联预览；确认后删除条目及其子孙，清理所有方案中的挂载，关联节点标红待修复。
- Given 关闭并重开项目，Then 层级、引用、版本和草稿/正式状态可恢复。

## 实现合同

条目 schema 为 `nbook.outline-entry/v2`，v1 文件仍可读取并在解析时归一为 v2。参考文件为 `references: {path?, locator?, purpose?, pending?}[]`：非待补项必须有 `path`，待补项可无路径但必须用 `locator` 说明所需资料，旧 `referenceFiles` 路径数组读取时转换，二者同时出现即拒绝。写作指导的场景锚定与按场景篇幅用细纲正文内的 `<!-- nb:guidance marker scene words -->` 成对注释表达，解析 fail-closed，只允许出现在细纲；场景篇幅不与章节 `targetWords` 做一致性校验。进入正式分析的细纲必须是当前规范序列化，否则提示先保存一次，避免采用后正文交接因来源 hash 不一致而失效。工作台大纲库已提供方案链、条目、共享条目写时分叉、上述字段以及细纲分析与正式采用的编辑界面，写入全部经领域操作，删除先预览影响；浏览器验收未执行。其余进度见 [t04](../../../.agents/works/w00018-outline-planning-module/tasks/t04-outline-library-and-detailed-outline/README.md)。实现不得将 Plot 实体复制为第二套 Scene 真相源。
