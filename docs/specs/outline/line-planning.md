# 线路规划

## 目标与非目标

本能力在每个方案内维护一张共享的剧情节点图：节点放在“格×行”网格上，横向格号 0…n 就是方案内的全局剧情先后；主线、支线、角色线和 IF 线是在图上勾选节点组成的链，可以从主线分出、互相汇合、最终汇回主线。已固定线路中的有效节点是正文写作的正式大纲入口。

本能力不把大纲库层级当作剧情顺序，不让行号承载剧情含义，也不允许失效、空白或未分析的节点进入正文。

## 术语与参与者

- **线路图**：一个方案唯一的一张图。节点和连线不带线路类型。
- **节点**：图中的对象，位于 (格号, 行号)，关联该方案中的一个非细纲条目，或暂时为空。
- **连线**：从小格号节点指向大格号节点的有向边，可以跨格，同格节点之间不能连线。
- **线路**：对节点集合的分类。按格号排序后格号严格递增、相邻节点之间有连线、至少 2 个节点，这样的线路称为链。分叉和汇合通过多条线路共享节点表达，单条线路内部不分叉。
- **主线**：每个方案最多一条。IF 线是方案内部的分支，不是方案 A/B。

## 规范文件

- `outline/graphs/<slug>--<gr-id>.yaml`，schema 为 `nbook.outline-graph/v1`，内容为 `{id, planId, version, nodes[{id, entryId|null, column, row}], edges[{id, from, to}]}`。
- `outline/storylines/<slug>--<ln-id>.yaml`，schema 为 `nbook.outline-line/v3`，内容为 `{id, planId, version, title, type, fixed, nodeIds[], analysis?}`。线路内的顺序由节点格号派生，不另存业务顺序。
- `outline/manifest.yaml`（`nbook.outline/v2`）登记 `graphs` 和 `lines` 两组文件引用。

加载时 fail-closed 的不变量：
- 每个方案至多一张图，同一格同一行只能有一个节点；
- 连线满足 `from.column < to.column`，不能重复，因此图必然无环；
- 节点条目属于本方案的 placements 且不是细纲；
- 同一张图内一个条目最多对应一个节点；
- 线路节点属于同方案的图，同一线路内不重复；
- 每个方案至多一条主线；
- 固定线路必须带分析报告，报告节点与线路节点一致。

结构化文件是规范来源，SQLite 只是可重建索引。

## 输入与前置条件

用户在画布上新建节点（可以先留空）、拖动节点吸附到“格×行”、关联或解除条目、从小格号向大格号连线、插入列（格号 ≥ c 的节点整体右移一格），然后进入勾选模式逐个点选节点组成线路。草稿线路可以暂时不是合法链；固定前必须通过结构校验和 AI 语义分析，并逐项处理冲突。

## 输出与可观察行为

画布显示顶部格号标尺、节点标题、状态色和所属线路色标，侧栏列出线路、类型、固定状态和链是否有效。节点状态：

| 状态 | 条件 |
|---|---|
| 有效 | 所在固定线路的结构与条目内容均与分析报告一致 |
| 黄 | 条目被修改、方案上下文变化、结构与报告不符或线路未固定 |
| 红 | 关联条目文件丢失 |
| 空 | 节点尚未关联条目 |

含空节点或红黄节点的线路不能固定，也不能用于正文。

## 状态与转换

| 事件 | 结果 | 拒绝条件 |
|---|---|---|
| 新增节点 | 图中新节点，可为空 | 单元格已占用；条目不在方案、是细纲或已在图中 |
| 移动节点 | 更新格号或行号 | 单元格已占用；连线会变成向左或同格；属于固定线路的节点改格号 |
| 插入列 | 格号 ≥ c 的节点右移一格 | 无；相对顺序不变，不使固定线路失效 |
| 关联或解除条目 | 更新节点条目 | 节点属于固定线路；条目不合法或已在图中 |
| 连线 | 新增有向边 | 向左、同格、重复或端点不存在 |
| 删除连线或节点 | 预览影响后确认提交；节点从草稿线路中移除 | 属于固定线路的节点或相邻连线；预览已过期 |
| 创建或编辑草稿线路 | 保存标题、类型和勾选节点 | 节点不在本方案图中或重复；第二条主线 |
| 分析并固定 | 固定线路，锁定节点格号、条目和相邻连线 | 不是链、含空节点或红黄节点、冲突未处理 |
| 重开固定线路 | 回到草稿并清除分析 | 未确认 |
| 切换主线 | 目标成为主线，旧主线降为支线并回到草稿 | 未确认或版本变化 |
| 修改或删除关联条目 | 固定线路回到草稿或节点标红 | 分析或修复前不可用于正文 |

固定线路锁定的只是它自己的结构：锁定节点可以改行号，也可以连向新节点或在旁边新建节点，这样可以从已固定的主线继续分出支线。

## 副作用与数据

分析报告的 `sourceHash` 覆盖线路标题、类型、按格号排列的节点与条目，以及相邻节点间的连线，不含绝对格号和行号，所以插入列不会使报告过期。

`contextHash` 覆盖方案 placements 和条目内容 hash。同方案其他固定线路只作为分析参考，不进入 `contextHash`，否则固定一条线路会让其他固定线路全部失效。

所有变更经规划事务发布并进入历史。

## 失败与恢复

结构化文件损坏或不变量不成立时读取 fail-closed，并保留原文件。原始文件发布入口拒绝修改线路图和线路文件，这些文件只能由领域操作转换。条目文件丢失时可以受限修复：图中引用它的节点改为空节点，涉及的固定线路回到草稿。

## 边界与兼容

本能力拥有方案内的正式剧情顺序和线路固定语义，不拥有条目正文的编辑权，也不拥有正文写入权。不得双写 Plot 的 Story、Thread 或 Scene。

旧版 `outline/lines/` 文件（`nbook.outline-line/v1`、`v2`）不兼容：读取 `nbook.outline/v1` manifest 时丢弃旧的 `lines` 引用，旧文件原样留在磁盘上但不再读取或显示，下次发布时 manifest 写为 v2。迁移说明见 [线路图格式替换](../../../packages/neuro-book/docs/migrations/outline-line-graph.md)。

## 验收与 Smoke

- Given 设计图示的结构（主线分出支线、支线2和角色线，中途两两汇合，最终汇回主线），When 按格号建图并勾选四条链，Then 每条线路都可以分别分析并固定，共享的分叉和汇合节点同时属于多条固定线路。
- Given 同一方案两条固定线路，When 某节点在格 3 埋设伏笔、另一线路格 5 的节点回收，Then 回收有效，已过格数为 2；在同格回收则报告回收早于埋设。
- Given 固定线路，When 在它前面插入列，Then 线路仍有效，已过格数随格号重算。
- Given 固定线路的节点，When 尝试改格号、改条目或删除它的相邻连线，Then 操作被拒绝并提示先重开。
- Given 含空节点的线路，Then 不能固定。
- Given 被引用条目被修改或删除，Then 节点分别显示黄或红，修复或重新分析前不可用于正文。

## 实现合同

服务端实现线路图与 v3 线路的格式、加载不变量、领域操作（图操作、线路操作、删除预览、主线切换、重开）、语义分析与固定、节点状态检查和缺失条目修复；伏笔与正文交接按格号派生。工作台用 vue-flow 画布提供吸附网格、格号标尺、连线拦截和勾选建线路。浏览器和真实模型验收完成前，本 Spec 维持 planned。
