# 全局提示词管理

## 目标与非目标

全局管理设计工作台（含提取）、大纲规划和写作模块所有 Agent 与直接模型调用的提示词、预输入消息及预设。暂不支持小说项目覆盖。编辑提示词不扩大工具权限，不改变业务解析、审批、写入或模型参数。

写手原生酒馆格式及其宏状态、消息转换和审阅记录见 [写手兼容](../writing/tavern-preset-compatibility.md)，不套用下文的普通平面条目编辑规则。专用编辑器提供本地 JSON 导入、原生顺序/角色/启停/正文编辑、相对/深度位置与触发类型、legacy/native 宏引擎、文本请求后处理、身份与资料绑定、变量初值与隔离选项、参数覆盖、正文提取、预览和两种配置导出；编辑后显式保存同 ID 新修订，开关不单独即时保存。可显式启用三个词表之一的上下文预算、填写含输出的总额度并选择示例优先；报告标明后处理前编排占用及裁剪数量。绑定/预算/原生 JSON 的应用只修改草稿，保存后生效；插件字段保留并提示不执行。

## 术语与参与者

调用用途由模块和阶段确定，不绑定 Provider 或模型型号。预设包含名称和有序条目；条目有稳定 ID、名称、正文、启用状态及 system/user/assistant 角色。assistant 是前置示例回复，不视为真实模型生成。内置默认由应用持有，自定义预设由用户持有。快照是会话或任务创建时固定的不可变提示词集合；写手每次生成或重试单独固定当时最新的配置。

## 输入与前置条件

配置中心 → 全局 → 提示词管理，不需要打开作品。用途列表按三个模块分类，标注名称与作用。选择预设供新会话使用；新建预设复制当前内容；内置仅能查看或复制，不能修改、删除、重命名或排序。服务端必须独立拒绝内置写入请求。

自定义预设允许新增、删除、重命名、排序和启用/停用条目，支持三种角色及用途公开的动态变量。停用条目保留名称、角色、正文和位置，运行时不展开变量、不发送。新条目默认启用，旧条目没有启用字段时按启用处理，历史快照原哈希保持不变。模板变量只替换一次；插入的作品正文中的变量语法不执行。未知变量或已启用条目缺少必需变量时保存失败，关闭必需任务模板时明确提示恢复启用。

## 输出与可观察行为

窗口约占屏幕三分之二面积，延续配置中心分类导航。用途旁提供预设下拉和删除/新建/编辑；内置“编辑”可改为“查看”。编辑页条目按手柄、名称、角色选择、启用开关、删除排列，点击名称展开正文和右下角保存。停用状态可辨识，页脚显示启用数量。内置正文和控件（含开关）只读，提供复制编辑。

保存按钮原子提交整个预设的名称、条目内容、角色、顺序、新增和删除；底部另提供同义保存，空条目列表仍有提交入口。多处同时编辑时使用配置版本拒绝过期覆盖，保留当前草稿并可刷新重试。切换预设立即改变全局选择，但不修改旧会话。

## 状态与转换

列表进入编辑时复制已保存预设为草稿；未保存不生效。返回列表、切换配置分类或作用域、关闭窗口丢弃草稿。保存成功才更新持久配置。删除自定义预设需要确认；删除当前预设后选回内置默认，历史快照保留。

写手场景正文与局部改写的已保存条目开关是显式保存的例外：切换时独立提交该条目启用状态，不提交尚未保存的正文、名称、角色、顺序、新增或删除；成功后更新草稿并发基线，保留其余未保存编辑。新建但未保存的预设或条目，开关暂时禁用并提示先保存。失败保留原开关状态和正文草稿；服务端拒绝内置、未知条目、过期版本和导致必需变量缺失的切换。其他用途的开关仍随整个预设显式保存。

新聊天记录固定创建时的快照，后续交流、追问、专家及写作子流程继承该快照。旧记录无版本信息时采用内置基线并固定，不能套用用户当前自定义。提取和其他无聊天流程以新任务为边界，重试、审阅修改及恢复沿用同一快照。应用重启后恢复相同版本。

分叉聊天沿用源聊天的快照。写作主创聊天被归档后，已有写作任务的主创和助手仍使用原快照，不因为聊天归档而改用新全局配置。写手接收助手细纲，不负责安排剧情；接入提示词管理的每次写手生成、重试和局部改写采用创建该次写手时的最新全局配置，包括开关、已保存正文和预设选择。已开始的请求与它的后续审阅保持同一次快照；切换不修改已生成正文。提示词管理接入前没有 managed 用途的历史写作流程仍按原模板重放。大纲方向草案和一致性审查是一次性请求，每次发起时采用当前全局配置。

## 副作用与数据

全局预设和不可变快照由 App State 持有，与作品容器隔离；版本引用由创建会话或任务的 owner 持久化。默认资产只读。动态原文、人设、章节、反馈不保存为全局预设；在调用时由业务流程填入。快照保存完整模板和静态提示依赖，删除预设或升级默认不清理历史引用版本。

## 失败与恢复

保存失败不替换已保存配置；版本冲突不覆盖其他修改。快照缺失或内容损坏明确失败，不自动改用新全局配置。模型、原文、业务校验和取消失败沿用各模块原语义。退出未保存草稿不触发模型或文件写入。

## 边界与兼容

新的当前配置快照声明 `messageOrder: configured`，按条目顺序保留全部已启用消息的角色、正文及边界。OpenAI Chat Completions 与 Responses 兼容接口逐条发送 system/user/assistant，system 不合并、不前移、不自动改成 developer；同角色相邻条目也保留为独立消息。普通交互追加在完整预输入之后；写手纯流程模板替换原任务提示，不能同时把旧模板追加回来覆盖用户修改。写手审阅保留该次实际有序序列。请求日志记录 Provider 回调转换后的最终请求体。

Pi 的通用 Context 不接受历史中的 system 消息，应用在 Provider 原生 payload 边界通过正式 onPayload 扩展注入有序预输入；保留后续会话、附件、工具和原有回调。OpenAI 以外接口沿用原生独立系统字段，仅接受最多一条位于预输入首位的 system；多条或交错 system 明确失败并提示改用能表达此结构的接口，不静默合并或转换为 user。这些接口的原生角色映射及消息合并约束不承诺与 OpenAI 完全一致。

既有快照未声明发送格式时继续按原独立系统字段合并的方式发送，不能因应用升级改变已有会话版本；无绑定的历史会话采用旧内置基线。新写手尝试使用当前有序配置，旧写手尝试及其审阅保持原格式。写手的两个用途（场景正文、局部改写）默认按小节拆成逐条条目，每条可独立排序、启用停用和改角色；承载事实性数据的条目所带变量是必需变量，停用会在保存时被拒绝，不再由程序在末尾追加一条消息把缺失的事实补回。新提取请求先按序发送配置条目，再追加本单元原文与补充资料，修复时将修复用途的完整序列追加在后。旧提取任务维持原原文/目标/修复拼接。

结构化输出和工具权限仍由领域合同校验。内置保护必须同时存在于界面和服务端。

写手的酒馆预设编辑器提供按原生写作条目配置的映射列表，排除职责与输出要求，按类别显示条目和目标下拉。目标同时包含资料占位符与预设定义、使用的固定名自定义变量；缺失目标不自动改写，停用或未读取字段不可选。多个条目可选择同一目标，未映射必需资料时保存被拒绝。变量初始化、映射及实际读取的行为见[写手酒馆预设兼容](../writing/tavern-preset-compatibility.md#写作条目映射)。旧配置显式转换，新导入默认开启；所有映射随预设显式保存。

每个写作小节提供“直接排序／变量映射”按钮，直接条目进入原生提示词序列，与酒馆条目共同拖动排序、编辑角色和正文；切回映射从源文件移除对应直接条目，恢复之前的映射目标并保留直接模板改动，避免重复发送。序列手柄支持指针拖动及键盘上下键，拖动所选条目时以原相对顺序移动选中组。序列与未加入序列条目均可多选，全选涵盖所有源条目；支持单条删除和批量删除，删除同时清除 prompts、全部角色 prompt_order 的引用及同名资料绑定。移出序列仍保留源条目。上述操作只修改草稿，显式保存后作用于新尝试，历史快照不变；删除必需资料后保存仍拒绝。

## 验收与 Smoke

- 内置可查看或复制，尝试保存、删除、改名及排序均被拒绝；复制的自定义预设可编辑保存。
- 同一预设修改多个条目并排序后保存，刷新恢复一致；未保存离开则恢复原内容。
- 新会话发出的请求含前置 assistant/user 和系统内容；旧会话追问、专家调用及恢复保持原版本。
- 新提取任务使用最新配置，既有任务重试和审阅修改保持旧版本。
- 删除自定义预设后，绑定它的历史仍可恢复；版本损坏明确报错。
- 长文本与 390px 窄屏不撑大窗口，内容可滚动且保存和关闭可达。
- 其他用途切换开关未保存离开恢复；保存后停用内容不进入新请求，旧会话继续使用原启用状态。
- 写手开关即时保存但不提交正文草稿；下一次生成或重试采用最新开关，已开始的写手与审阅保持原快照。
- 写手用途下停用承载必需变量的小节（如场景地点）被服务端拒绝；停用「禁用写法」「样文」这类可选小节可以保存。
- OpenAI 兼容请求实际收到 system → user → system → assistant 原序列，相邻同角色条目独立，停用条目不发送；日志与实际请求体一致。
- 旧快照保持原格式，普通会话续聊不重复注入预输入，写手请求不追加过时任务模板；其他接口对不能表达的多条或交错 system 明确失败。
