# 写作问题回流

## 目标与非目标

写作时发现的规划缺口会被记录下来，例如细纲缺少场景结构、参考资料缺失、写作指导互相矛盾。这些问题显示在写作界面上，用户可以跳回大纲工作台处理；规划修改后，写作模块会重新复核这些问题。

本能力不修改大纲、伏笔或参考文件，也不自动修复问题。

## 术语与参与者

- **写作问题**：写作或改写过程中登记的一条记录，归属某一章。
- **阻断**：会让本次写作停止的问题级别。
- **提示**：不停止写作，只列在报告里的问题级别。
- 参与者：
  - 助手：规划场景或审阅时登记问题；
  - 写作工作流：校验和版本检查失败时登记问题；
  - 主创：向用户报告问题；
  - 用户：查看、跳转或忽略问题。

## 输入与前置条件

- 登记问题时，本章有写作方案中的章节归属（见 [writing.prose-binding](prose-binding.md)）。
- 登记问题时，写作工作流记录当时细纲与章节大纲的版本。

## 输出与可观察行为

### 问题记录

每条问题包含：

- 问题 id、章节条目 id、级别（阻断或提示）；
- 问题代码与说明；
- 相关位置：细纲条目 id，可带场景编号；
- 登记方：助手或写作工作流；
- 登记时的章节大纲版本与本章各份细纲的版本；
- 状态：未处理、待复核、已解决、已忽略；
- 登记时间。

常见代码：

| 代码 | 级别 | 说明 |
|---|---|---|
| `MISSING_SCENE_STRUCTURE` | 阻断 | 细纲结构不完整：缺章节总览或目标字数、没有场景、场景编号不连续、场景缺场景简述、字数、人称或具体情节、伏笔标记或状态与章节大纲不一致；或本章有多份细纲 |
| `PLANNING_CHANGED` | 阻断 | 写作过程中规划版本变化 |
| `SOURCE_UNREADABLE` | 阻断 | 文风文件或参考文件不可读 |
| `GUIDANCE_CONFLICT` | 阻断 | 写作指导之间相互矛盾，无法同时满足 |
| `PENDING_REFERENCE` | 提示 | 细纲引用的参考资料尚未补齐 |
| `WORD_TARGET_MISMATCH` | 提示 | 本章各场景字数要求之和与细纲总览目标字数相差超过 50% |
| `UNASSIGNED_FORESHADOW` | 提示 | 章节大纲中的伏笔标记没有分给任何场景；或场景认领的标记属于尚未确认的伏笔，写作不执行 |
| `MISSING_PREVIOUS_CHAPTER` | 提示 | 上一章尚无正文 |

助手也可以登记上表以外的问题。这类问题的代码固定为 `OTHER`，级别和说明由助手填写。

### 登记时机

- 助手在规划场景或审阅时登记。
- 写作工作流在程序校验、版本检查或读取失败时登记。
- 一次写作中出现阻断问题时，写作停止，主创向用户报告问题说明和相关位置。写作完成后，主创在完成报告中列出本次登记的提示问题。
- 同一章中代码与相关位置都相同、且仍处于未处理或待复核的问题不重复登记，只更新登记时间。

### 显示与跳转

- 左栏大纲视图中，有未处理或待复核问题的章节显示徽标：
  - 有阻断问题时，徽标为阻断样式；
  - 只有提示问题时，徽标为提示样式。
- 点击徽标展开问题列表。每条问题都有“在大纲工作台中打开”，跳转到对应细纲，并尽量定位到对应场景或标注。
- 写作会话中，主创报告问题时附带同样的跳转入口。

### 复核与关闭

- 章节大纲或本章任一份细纲的版本与问题记录中的版本不一致，或本章细纲有增减时，问题显示为“待复核”。
- 下一次对这一章发起写作时，写作工作流和助手重新检查所有待复核问题：
  - 已不存在的，标为“已解决”；
  - 仍存在的，回到“未处理”，并更新版本。
- 提示与阻断问题都可以由用户忽略。忽略后不再显示徽标，下次写作也不再报告；同一问题再次登记时保持已忽略，不因该条目停止写作。
- 忽略关闭问题记录，不修改规划或参考文件。缺失文件、细纲无法解析、正文或资料版本冲突等操作前置条件仍会检查；不能通过忽略使无效输入可用。

## 状态与转换

| 当前 | 事件 | 下一状态 |
|---|---|---|
| 无 | 登记 | 未处理 |
| 未处理 | 细纲或章节大纲版本变化 | 待复核 |
| 待复核 | 复核后问题已不存在 | 已解决 |
| 待复核 | 复核后问题仍存在 | 未处理 |
| 未处理 / 待复核 | 用户忽略 | 已忽略 |

“待复核”根据当前版本与记录中的版本派生，不需要额外写入。

## 副作用与数据

- 写作问题按章节保存在 Project 内的写作模块数据中，属于可审查的产品数据。
- 不写入任何大纲、伏笔、线路或 `lorebook/` 文件。
- 所属章节从当前写作方案中移除后，问题记录保留但不在视图中显示；重新纳入后恢复显示。尚未写出正文或正文解除关联不隐藏问题。

## 失败与恢复

- 问题记录读取失败：徽标不显示，左栏提示“问题记录读取失败”，不影响写作。
- 问题记录写入失败：本次写作按原逻辑继续或停止，主创在报告中说明问题未能保存。
- 跳转目标条目已不存在：打开大纲工作台并提示条目已不存在。

## 边界与兼容

- 问题只描述写作侧看到的情况；是否修改规划、怎么改，由用户在大纲工作台中决定。
- 本能力只读取规划版本，不依赖大纲模块内部的审阅状态格式。

## 验收与 Smoke

- Given 细纲没有场景一级标题，When 发起写作，Then 写作停止，登记 `MISSING_SCENE_STRUCTURE` 阻断问题，左栏该章显示阻断徽标。
- Given 某问题已登记，When 用户修改并保存细纲，Then 该问题显示为“待复核”。
- Given 问题待复核，When 再次发起写作且问题已不存在，Then 问题标为“已解决”，徽标消失。
- Given 提示级问题，When 用户忽略，Then 徽标消失，下次写作的报告不再列出它。
- Given 阻断级问题，When 用户点击忽略，Then 条目关闭，徽标消失；同一问题再次登记保持忽略，写作不因该条目停止。
- Given 尚未写出正文的章节登记阻断问题，Then 问题也显示在该章，可以点击忽略。
- Given 点击问题的跳转入口，Then 打开大纲工作台并定位到对应细纲。
- Given 同一问题在两次写作中都被登记，Then 只保留一条记录。

Smoke：用缺少参考资料的细纲写作一章，确认完成报告列出 `PENDING_REFERENCE`，左栏显示提示徽标；补齐资料后再次写作，问题标为“已解决”。

## 实现合同

已实现问题记录的存储、状态派生和查询，写作工作流中的登记与复核（见下文“写作工作流中的登记”），以及大纲视图中的徽标、问题列表、忽略与跳转（见 [writing.workspace-ui](workspace-ui.md) 的实现合同）。跳转只定位到问题所在条目，不定位到场景或段落标注。

### 模块

- `server/writing/issues.ts`：记录格式、登记去重、状态派生、复核、忽略，都是纯函数。
- `server/writing/host.ts`：按章读写问题文件，并做登记校验。
- DTO 在 `shared/dto/writing.dto.ts`：`WritingIssueDto`、`WritingChapterIssuesDto`、`WritingIssuesDto`。

### 文件

- 路径：`writing/issues/<章节条目 id>.yaml`，每章一个文件；写入走项目历史。
- 格式：`{schema: nbook.writing-issues/v1, chapterEntryId, issues: [...]}`，文件中的 `chapterEntryId` 必须与文件名一致。
- 每条记录的字段：
  - `id`：`wi-` 加小写字母数字；
  - `code`、`severity`、`message`、`location {entryId?, sceneIndex?, guidanceMarker?}`；
  - `registrar`：`assistant` 或 `workflow`；
  - `basis {chapterVersion, details[{entryId, version}]}`：登记时的版本；
  - `status`：`open`、`resolved`、`ignored`；
  - `registeredAt`。
- 内容不变时不写盘；没有文件且没有记录时也不创建文件。

### 状态与登记

- 待复核不写入，查询时派生：
  - 记录为 `open`，且章节大纲版本不同、任一份细纲版本不同，或细纲有增减时，显示为 `pending-review`；
  - 只比版本号，不比内容哈希；细纲只调整顺序不算变化。
- 固定代码的级别必须与上表一致，只有 `OTHER` 可以自填级别。
- 同一问题的判定：
  - 代码相同，且位置的三个字段都相同；
  - `OTHER` 另外要求说明相同（去掉首尾空白后比较）。同一位置可能登记多条不同的 `OTHER`，只按位置合并会丢失其中的问题。
- 同一问题再次登记：
  - 仍为 `open` 的，更新登记时间和版本，复核后仍存在的问题由此从待复核回到未处理；
  - 已忽略的问题保持忽略，只更新登记时间和版本；
  - 已解决的问题重新打开，级别、说明和登记方取本次登记的值。
- 登记时，`location.entryId` 必须是本章的章节大纲或本章的细纲，否则拒绝整批登记。

### 复核与忽略

- 复核：按 id 把 `open` 的问题标为 `resolved`；已解决和已忽略的记录不变；id 不存在时报错。
- 忽略：
  - `open` 的提示与阻断问题都可以忽略，待复核的问题也在此列；
  - 已解决的问题拒绝忽略；
  - 已忽略的再次忽略不做改动。

### 写作工作流中的登记

见 [writing.collaboration](collaboration.md) 的实现合同。

- 登记方：
  - 程序在准备、规划校验、场景开始前、写入依据时发现的问题，登记方为 `workflow`；
  - 助手随规划或审阅提交的问题，登记方为 `assistant`。
- 本次提交中仍未处理的阻断问题会停止运行；已忽略的记录不阻断。登记失败写进运行结果的附注，此时仍按提交的原始级别判断，不能把保存失败当作用户已忽略。
- 场景规划通过核对后复核一次，把本次运行开始前登记、本次没有再登记的旧问题标为已解决：
  - `workflow` 的问题：每次都由程序重新检查，没有再登记即视为已消失；
  - `assistant` 的问题：只处理已派生为待复核的，版本未变的保持未处理。
- 依据未变、沿用上次规划的续写不再规划，也不做这次复核。
- 运行结果列出本次运行登记、且仍未处理的提示问题。

### 可见范围

2026-10-10 开发者要求阻断条目也可忽略；查询范围同步扩展至当前方案所有章节，确保正文创建前的阻断也有处理入口。

- 列出的条件：章节在当前写作方案中，不要求已经创建或关联正文文件。
- 不满足时记录保留在磁盘上，查询不列出；重新纳入方案后恢复显示。
- 登记只要求章节在当前方案中。尚未写出正文时的问题也显示徽标并可忽略。

### 接口

- HTTP，路径在 `/api/projects/writing/` 下：
  - `GET issues` 返回 `{chapters: WritingChapterIssuesDto[], unreadable: [{chapterEntryId, message}]}`，只列有记录的章节；
  - `POST ignore-issue`，请求体为 `{chapterEntryId, issueId}`，返回该章的 `WritingChapterIssuesDto`。
- 登记和复核只供服务端调用，不开放 HTTP：`registerReadyWritingIssues`、`resolveReadyWritingIssues`。
- 徽标计数：`blocking`、`hint` 只统计 `open` 与 `pending-review` 的记录。
- 问题查询与写作概览分开：问题文件损坏或读取失败，不影响概览。

### 错误

| 代码 | HTTP | 情形 |
|---|---|---|
| `ISSUE_INVALID` | 400 | 问题草稿格式非法、级别与代码不符，或位置不属于本章 |
| `ISSUE_NOT_FOUND` | 404 | 复核或忽略的 id 不存在 |
| `ISSUE_NOT_IGNORABLE` | 409 | 忽略已解决的问题 |
| `ISSUES_UNREADABLE` | 422 | 本章问题文件损坏，拒绝写入 |
| `CHAPTER_NOT_IN_PLAN` | 404 | 章节不在当前方案中 |

问题文件损坏时的处理：

- 查询把该章列入 `unreadable`，其他章节照常返回；
- 写入该章时报 `ISSUES_UNREADABLE`，不覆盖原文件。问题文件不像写作设置那样可以整体重建，覆盖会丢失其中仍然有效的记录。

  - 切换方案后不列出，切回后恢复；
