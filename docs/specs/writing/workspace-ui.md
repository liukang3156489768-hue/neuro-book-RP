# 写作界面

## 目标与非目标

在项目工作台里提供写作界面：

- 左栏按写作方案映射大纲与正文；
- 中间显示所点的内容；
- 右栏是按章节划分的写作会话。

用户在这里选章、发起写作、查看进度、修改正文和发起局部改写。

本界面不编辑大纲规划，不另建一套会话界面，也不自行推断章节是否可写。

## 术语与参与者

- **大纲视图**：左栏新增的视图，属于“大纲”容器。
- **写作会话视图**：右栏新增的视图，属于“写作”容器。
- **写作会话**：一章对应的一个 Agent 会话，固定使用主创 Profile。
- **进度卡片**：写作会话中显示本次写作或改写进度的卡片。
- 参与者：用户，以及写作工作流（推送进度）。

## 输入与前置条件

- Project 已打开。
- 章节树和章节状态来自正文与规划的绑定（[writing.prose-binding](prose-binding.md)）。写作和改写的执行行为见 [writing.collaboration](collaboration.md)。
- 写作方案为空时，大纲视图只显示方案选择入口。

## 输出与可观察行为

### 左栏：大纲视图

- 工作台左侧活动栏在“文件”旁边新增“大纲”入口。点击后，左栏切换为大纲视图；再点“文件”回到文件列表。
- 顶部显示当前写作方案，可以切换；还有写作设置入口，用于选择文风文件。
- 文风选择框旁有“编辑”“新增”“删除”三个按钮：
  - 编辑：在中间编辑器打开当前文风文件，由用户直接修改；
  - 新增：选择框下方出现名称输入框，创建后在编辑器打开新文件；
  - 删除：同一位置出现确认，确认后删除当前文风；有进行中的写作运行时不可用。
- 空选项显示“未选择（写作前必须选择）”；未选文风时提示先选择或新增。
- 树的层级与大纲库中写作方案的层级一致：
  - 卷纲
    - 章节大纲
      - 细纲（一份或多份）
      - 正文
- 没有上级卷纲的章节归在“未分卷”下。卷和章节的顺序与大纲库该方案中的顺序一致。线路规划不影响这棵树的内容和顺序。
- 每个章节显示写作状态：
  - 不可写的章节灰显，并标出原因：大纲未采用、细纲未审阅、归属冲突；
  - 可写的章节标出：未写、已写、依据已过期；
  - 有未处理问题的章节显示问题徽标（见 [writing.issue-feedback](issue-feedback.md)）。
- 树末尾是“未关联正文”分组，列出 `manuscript/` 下没有归属的章节文件，并提供关联和解除关联操作。
- 大纲条目在这里只读，不提供新建、删除、改名或拖动。
- 规划或正文文件变化时，树与状态自动刷新。刷新时保持展开状态和当前选中项。

### 中间：内容显示

| 点击 | 中间显示 |
|---|---|
| 卷纲、章节大纲、细纲 | 只读显示条目正文，按大纲工作台的样式呈现 |
| 正文 | 在项目富文本编辑器中打开，可编辑 |
| 尚无正文的“正文”节点 | 空状态，说明这一章未写；可写章节提供“开始写作”入口，它会切到右栏并由主创接手 |

- 只读页上有“在大纲工作台中打开”入口，跳转到大纲工作台中的对应条目。
- 这一章正在运行写作或改写时，正文编辑器只读，并提示“写作进行中”。运行结束后自动恢复可编辑，并载入最新内容。

### 右栏：写作会话视图

- 右栏新增“写作”容器，内嵌项目现有的 Agent 会话界面，不另建会话界面。
- 嵌入时有以下限制：
  - Profile 固定为主创，不可切换；
  - 会话列表只显示写作会话；
  - 新会话自动绑定当前章节。
- 一章可以有多个会话。左栏选中章节（包括选中它的细纲或正文）时，右栏切换到这一章最近更新的会话；这一章还没有会话时，第一次发送消息时创建。
- 右栏头部的会话控件：
  - 会话下拉：列出这一章的会话，按更新时间倒序，可切换；
  - 新建：另开一个会话并打开，旧会话保留；
  - 删除：内联确认后归档当前会话，改开剩下最近的一个；这一章有写作运行、主创正在回复或等待回答时不可用，并说明原因；
  - 主创回复中、提交待确认中不能切换、新建或删除会话。
- 选中灰显章节时仍可查看它的历史会话，但输入框禁用，并显示不可写的原因。
- 右栏顶部显示当前章节标题和状态。
- 模型设置入口位于底部输入区下方左侧，待回答问题时仍保留；弹出面板分别设置主创、助手、写手的模型、思考（含“关闭思考”）和温度，空白沿用全局设置，保存在本作品。
- 对话区域在主创对话后显示写手输出条目，按运行、场景与尝试次数区分，局部改写也适用。每个条目默认折叠，展开后查看模型返回的思考内容与正文，各自限高滚动；展开正在生成的条目时流式更新。未通过审阅的尝试同样可查看，展示不表示已写入正文文件。
- 收起时不读取写手会话或保持其事件流；读取失败可以重试，主创对话与已有正文照常显示。模型没有返回思考内容时明确说明。刷新后从运行记录恢复关联，条目重新默认折叠。

### 进度卡片

- 发起写作或改写后，会话中出现进度卡片，写作期间持续更新。
- 写作的进度卡片：
  - 准备完成即显示整章场景列表，每个场景显示状态：待规划、规划中、待写、写作中、审阅中、重写第 N 次、已通过、未通过；
  - 展开场景，可只读查看渲染后的写手提示和审阅结果；
  - 按钮：“停止”在运行时可用；“继续”在已停止时可用，从第一个未通过的场景继续；
  - 讨论模式下，每个场景规划独立审核、主创核对通过后，卡片只显示当前场景规划摘要，以及“确认场景”“退回修改”两个操作；确认后开始下一个场景规划，全部确认后才开始正文写作；
  - 自动模式由独立审核助手逐场景审核并推进，无用户确认控件；退回仅重做当前场景；停止后继续沿用已确认规划。
- 改写的进度卡片：
  - 显示目标段落和新段落的对照；
  - 提供“替换”和“放弃”；
  - 操作一次后，两个按钮都禁用。
- 进度卡片放在对话下方的“写作进度”抽屉里：
  - 默认展开，点标题收起或展开；
  - 抽屉内容限高约半屏并纵向滚动，卡片内的场景详情、写手提示、规划摘要和结果列表也各自限高滚动，卡片再长也不挤掉对话；
  - 收起时出现待用户确认的场景规划或改写，标题旁显示“等待确认”并自动展开。
- 刷新页面或重新打开项目后，进度卡片按运行记录恢复显示。

### 从编辑器发起改写

- 在正文编辑器中选中文字后，可以用“改写选中内容”把选区交给右栏这一章的会话，由用户补充修改要求后发给主创。
- 选区跨越多个段落时，全部涉及的段落都是目标。

### 布局

- 大纲视图和写作会话视图遵循工作台的视图移动规则，可以拖动到其他容器。
- 在 390px 宽的视口下，左右栏按工作台已有的窄屏规则折叠；树、会话输入框和进度卡片的按钮都不产生横向滚动。

## 状态与转换

| 当前 | 事件 | 结果 |
|---|---|---|
| 左栏为文件列表 | 点击“大纲”入口 | 左栏显示大纲视图 |
| 选中章节 A | 选中章节 B | 右栏切换到章节 B 的会话；A 运行中的写作不受影响 |
| 章节空闲 | 写作或改写开始 | 正文编辑器只读，出现进度卡片 |
| 运行中 | 用户点“停止” | 运行停止，编辑器恢复可编辑，卡片显示“继续” |
| 运行中 | 运行结束 | 编辑器恢复可编辑并载入最新正文，左栏状态刷新 |

## 副作用与数据

- 本界面只保存视图布局、展开状态、当前选中章节这些界面偏好，不保存领域数据。
- 正文编辑沿用项目富文本编辑器的保存与历史快照。
- 写作设置、关联和解除关联的写入见 [writing.prose-binding](prose-binding.md)。

## 失败与恢复

- 规划数据或状态读取失败：左栏显示错误和重试入口，已经打开的正文不受影响。
- 会话加载失败：右栏显示错误和重试入口，左栏和中间照常可用。
- 进度推送中断：卡片显示“连接中断”，重连后按运行记录补齐状态。
- 替换时目标段落已被改动：卡片提示替换失败，正文不变。

## 边界与兼容

- 章节状态和问题只显示服务端给出的结果，客户端不根据版本、哈希或条目状态自行判定。
- 不修改“文件”视图和现有 Agent 主界面的行为；嵌入会话界面只增加上面列出的限制，其余行为保持不变。
- 大纲工作台仍是编辑规划的唯一入口。

## 验收与 Smoke

- Given 打开项目，Then 左侧活动栏有“大纲”入口，点击后显示按卷、章节、细纲、正文组织的树，顺序与大纲库该方案一致。
- Given 在大纲库中调整两章的顺序，Then 大纲视图中两章的顺序随之改变；调整线路规划不改变大纲视图。
- Given 某章细纲未审阅，Then 该章灰显并标“细纲未审阅”，右栏输入框禁用并显示原因。
- Given 点击细纲，Then 中间只读显示细纲正文，没有编辑能力。
- Given 点击正文，Then 中间用项目富文本编辑器打开并可编辑。
- Given 在左栏从章节 A 切到章节 B，Then 右栏切到章节 B 的会话，Profile 为主创且不可切换。
- Given 写作运行中，Then 正文编辑器只读，进度卡片显示各场景状态，展开后能看到提示和审阅结果。
- Given 点击“停止”后再点“继续”，Then 从第一个未通过的场景继续。
- Given 在正文中选中一句话发起改写并确认替换，Then 只有目标段落被替换。
- Given 视口宽 390px，Then 大纲树、会话和进度卡片没有横向滚动。
- Given `manuscript/` 下有无归属的章节文件，Then 它出现在“未关联正文”中，并且可以关联到尚无正文的章节。

Smoke：在示例项目中切到大纲视图，选一章可写章节，在右栏让主创写作，观察进度卡片与正文逐场景增长；写完后选中一段发起改写并替换。

## 实现合同

已实现左栏大纲视图、中间只读条目与空正文页、右栏写作会话、进度卡片、编辑器运行期只读和“改写选中内容”入口，用组件测试、store 测试和 Mock 数据验证，并完成浏览器验收与真实模型 Smoke（见下文“验收记录”）。

### 模块

- `app/stores/writing-workspace.ts`：三处共用的界面状态（选中、展开、中间只读页、运行进度、预填输入），数据全部来自服务端，不在客户端判定章节状态。
- `app/utils/writing/writing-api.ts`：写作 HTTP 接口的客户端；`writing-tree.ts`：分卷、不可写原因、问题徽标、选中项与运行锁定的纯函数。
- 组件都在 `app/components/novel-ide/writing/`，各带同名 `.md`：
  - `WritingOutlineView`（左栏宿主）与 `WritingOutlineTree`（受控树）；
  - `WritingCentrePanel`：条目只读页与空正文页，复用 `OutlineEntryForm` 的只读模式；
  - `WritingSessionView`（右栏宿主，会话经 `app/composables/useWritingChapterAgent.ts`）与 `WritingRunCard`（受控进度卡片）。
- 两个宿主视图共用一个 store，而不是一个宿主向下传数据：工作台按描述符分别创建它们，可以拖到不同容器。

### 工作台登记

- 容器：`nbook.outline`（左侧，活动栏“大纲”）、`nbook.writing`（右侧，“写作”）。
- 视图：`nbook.writing-outline`、`nbook.writing-session`，都要求已打开项目与 `files` 权限，可按工作台规则移动。
- 右侧原有的 Agent 容器没有成员视图时不显示入口，所以右侧活动栏当前只有“写作”。

### 中间内容

- 条目只读页和空正文页盖在当前编辑器组上，不替换编辑器，已打开的正文不会被卸载。编辑器切换标签或打开其他文件时收起。
- 点正文直接在编辑器中打开；“在大纲工作台中打开”经 `outlineFocus` 打开工作台并定位条目。
- 编辑器只读：`useEditorWorkbench` 的 `lockReasonOf(path)` 返回原因时该组只读，并显示占用提示条（`EditorGroup` 的 `notice`）。锁定只挡界面输入，运行结束后的最新正文依靠工作区的磁盘同步重新载入。

### 改写入口

- 只在编辑器右键菜单中提供“改写选中内容”（`TipTapMarkdownEditor` 的 `canRewriteSelection` 与 `rewrite-selection`），选区浮动工具栏不变。
- 只对归属某章的正文显示；只读或没有选区时禁用。点下后把引用选区的文字预填到这一章会话的输入框，等用户补写修改要求；正文不归属任何章节时提示并不预填。
- 开始写作同样经预填，但会直接发送。

### 数据刷新

- 首次显示任一视图时读取概览、问题与文风候选；问题读取失败不影响概览，只提示“暂不显示问题”。
- 工作区磁盘事件：`outline/`、`manuscript/`、`writing/` 的变化合并后重读概览，只有 `writing/runs/` 的变化只重读运行；刷新后保留仍存在的展开与选中。
- 运行进度每 1.5 秒轮询一次，没有进行中的运行时停止；轮询失败显示“连接中断”，并保持上次的锁定，免得误放开编辑。
- 为界面新增的只读接口（`/api/projects/writing/` 下）：
  - `GET entry?entryId=`：当前写作方案中的卷纲、章节大纲或细纲条目（`WritingEntryDto`），方案外的条目返回 `CHAPTER_NOT_IN_PLAN`；
  - `GET styles`：`lorebook/instruction/` 下类型为 instruction、子类型为 writing-style 的文风候选；
  - `GET active-runs`：本项目进行中的运行摘要，供左栏“写作中”标记和编辑器锁定使用。

### 限制

- 问题只定位到条目：跳转打开问题所在的章节大纲或细纲，不定位到场景。
- 界面偏好（展开、选中、中间页）只保存在内存中，刷新页面后恢复默认。
- 解除关联只出现在“未关联正文”分组（关联失效）和归属冲突的正文上；正常归属某章的正文在界面上没有解除入口，服务端 `unlink-prose` 仍可解除。

### 验收记录

- 通过的验收条目：大纲入口与树顺序；细纲未审阅、大纲未采用灰显，输入框禁用并显示原因；细纲只读且段落标注可见，标注卡操作禁用；切换章节切换会话，头部为主创；写作运行中编辑器 `contenteditable=false` 并显示“写作进行中”提示条，结束后恢复可编辑并载入最新正文；停止后继续从第一个未通过的场景开始；选中一句改写并替换，文件前后比对只有目标段落变化；未关联正文关联到尚无正文的章节，候选排除已有正文的章节。
- 390px：浅色、深色下文档与树、会话、进度卡片、编辑器的 `scrollWidth` 都不超过 `clientWidth`；三栏按工作台规则纵向堆叠。
- 主题：`data-nb-appearance` 为 light、dark 时写作视图与卡片随配色变化。
- 未在浏览器中验证：在大纲库中调整章节顺序后树随之变化（由 store 测试覆盖）；问题徽标（真实运行没有登记问题，由组件测试覆盖）。
