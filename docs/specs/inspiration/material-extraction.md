# 作品素材提取

## 目标与非目标

用户选择一部作品，程序按固定流水线从中提取九类素材，整合后经用户审阅批量写入项目 `lorebook/`，并标记来源，供创作或改编时参考。

不承诺：提取大纲与细纲（见 [inspiration.outline-extraction](outline-extraction.md)）；“事件”与“参考资料”类别；原创设计新增写作手法与素材特点（这两类只能从作品中学习）；由 Agent 编排提取内容；工作台界面整理。

## 术语与参与者

- **来源与分块**：来源作品只读，沿用 P 段落编号与内容哈希；按约五万字切分为连续分块。有章节时完整章节不可拆分，超过目标的章节独立成块；无章节时按完整段落分组。大纲和素材使用同一组块号与 P 范围。
- **类别与处理模式**：

| 类别 | 处理模式 | 保存目录 |
|---|---|---|
| 角色 | 实体型 | `lorebook/character/` |
| 势力 | 实体型 | `lorebook/faction/` |
| 物品 | 实体型 | `lorebook/item/` |
| 地点 | 实体型 | `lorebook/location/` |
| 特殊规则 | 实体型 | `lorebook/system/` |
| 文风 | 文档型 | `lorebook/instruction/` |
| 世界观 | 文档型 | `lorebook/world/` |
| 写作手法 | 文档型 | `lorebook/note/写作手法/` |
| 素材特点 | 逐条收录 | `lorebook/note/写作素材/` |

- **实体型**：每个实体一个中间文件夹，逐块追加信息，最后整合为一份终稿。**文档型**：文风与世界观每块一份分析稿，最后整合为本类终稿；写作手法每块独立保存，不再进行跨块正文整合。**逐条收录**：素材特点绑定具体位置，没有可合并的名称，每条一个文件，不整合。写作手法与素材特点另由 AI 生成检索注释，程序汇成两个分类索引。
- **写作手法**：可迁移的通用技法。**素材特点**：落在具体章节或分块的特别剧情安排或表现形式。两者允许涉及剧情发展，是“素材模板不涉及剧情发展”规则的例外；其余类别仍遵守该规则。
- **中间产物**：存放在项目内部状态目录 `.nbook/inspiration/extractions/<任务 ID>/`，不属于 `lorebook/`。
- **用户**：归类、审阅、确认覆盖的人。**Agent**：只能下发任务、确认新条目的批量写入和接收失败上报，不编排提取内容。

## 输入与前置条件

- 项目已打开，已配置可用的提取模型；来源规则与大小限制同 [inspiration.outline-extraction](outline-extraction.md)。
- 素材提取与大纲提取是两类独立任务：状态分开保存，界面入口与进度面板分开，互不阻塞。
- 素材任务可选 `blocks?: number[]`；缺省选择全部块，块号必须存在且去重排序。任务参数持久化选择，恢复、重试和审阅只处理所选块。
- 用户可选择提取哪几类；默认全部九类。

## 输出与可观察行为

### 流水线

按分块顺序逐块处理；角色先对每个分块做一次轻量名单发现，再按候选覆盖率分为 A/B/C 级：A 级在每个出现分块单独提取，B 级在同一分块两人一组，C 级在同一分块三人一组。分组不能跨分块或跨等级，分组输出仍按角色独立校验和写入。其他八类仍按“分块 × 类别”独立调用模型，每次只提取一类。同一分块的请求保持“系统信息 → 原文 → 角色字段模板 → 动态目标 → 任务要求”的顺序，修复信息只能追加在末尾；原文与模板的稳定前缀用于 Provider 缓存，任务目标放在末尾。一块全部类别完成后再进入角色提取阶段。

角色名单发现只保存候选名称、别称和出现分块，不直接进入归类或整合索引。每个候选同时分配稳定角色 ID；任务内部仍用可读名称键定位中间片段，最终写入时使用稳定 ID作为 `lorebook/character/<stable-id>/` 目录名。角色等级仅用于任务编排，不进入角色模板或最终文件。覆盖率分母为当前任务所选块数：覆盖至少 40% 或至少 8 块为 A 级；其余覆盖至少 3 块为 B 级；剩余为 C 级。分组按稳定键值排序，不依赖系统区域设置。

分组 JSON 无法解析、角色集合缺失、重复或多出时，整组修复一次；仍失败或长度重试仍截断时，追加独立的单角色补提取单元。角色集合完整但部分字段或引用不合法时，校验通过的角色先独立保存，只为失败角色追加单人单元。单人单元沿用单元重试控件，手动重试不重新调用已成功角色。空资料角色确认处理完成但不产生空档案。网络、配置、来源和写盘错误不触发拆组，沿用既有失败与取消语义。重新执行角色发现时，已排队角色块仍由原单元拥有，只为新增角色块补排任务。

缓存前缀指纹包含系统消息、当前原文和角色模板，以及消息角色和边界；自定义示例、已知名单、目标与修复内容放在该公共前缀之后。模型日志关联任务、单元、分块、等级、角色组和指纹，记录实际 usage 的输入、输出、缓存读写计数；Provider 未返回时为 null。实际缓存命中率由 Provider 决定，本轮 Mock 验证不替代真实命中率验收。

实体型类别的调用在原文之后、任务之前附带当前已知实体名单（名称与别称），模型可输出已有实体的标准名称，程序据此追加到对应实体文件夹而不是新建；名单只出现在实体型调用的上下文中，不进入其他类别。

### 校验与修复重试

程序按模板校验每次产出：字段归属正确、必填信息完整、P 编号有效、引用位于本块范围内。不通过时，把本次产出与错误信息拼接到提示词末尾的预留位置（平时为空）后再次调用。同一发现单元、逐角色单元或“块 × 类别”单元连续失败两次，程序标记该单元失败并上报给 Agent 或用户，流水线继续处理其他单元。

角色输出示例包含完整的基础字段及 `references`、`experiences`、`relationships`。基础引用 `references` 与 `fields` 同级且必须是字符串；经历和关系分别在自己的“参考片段”字段中填写引用，不能替代基础引用。没有资料的字段留空，不能为了通过校验编造信息或引用。结构约束随动态任务要求发送，即使历史任务保留旧提示词快照，也能在重试时收到当前输出合同；不改写已保存的快照。校验失败后追加针对字段位置、类型、引用和 JSON 格式的修复要求，原文和模板前缀保持不变。

### 批量处理失败项

大纲和素材共用的“逐项状态”栏提供“一键重试（数量）”与“一键跳过（数量）”，处理点击时所有失败单元，不受当前列表筛选影响。运行中、待确认和部分失败时可用；无失败或请求进行中时禁用，已取消或已中断时先继续任务。

每次操作提交一次失败 ID 集合，由服务端在同一任务锁内重新核对状态、整批更新，暂停任务至多重启一次。已完成、已跳过或正在运行的单元不被重置，点击后新产生且未在集合中的失败不被处理；重复 ID 去重。未知 ID 使整批拒绝并提示刷新。来源哈希、项目访问和任务占用规则沿用单项操作。批量跳过保留已成功产物，后续流程按明确缺失的单元继续。切换任务或来源后，旧批量请求的响应不能覆盖当前页面。

### 中间产物

- 实体型：每个实体一个文件夹，内含各分块对该实体的提取片段；后续分块揭示新信息时追加到同一文件夹。
- 文档型：每个类别一个文件夹，每块一份分析稿；写作手法保留 `integrated/writing-technique/index.json` 分块定位表。两类 note 素材的 AI 检索注释分别保存在 `indexes/writing-technique.json` 与 `indexes/material-feature.json`。
- 逐条收录：每条一个文件，记录所在分块与 P 引用。
- 角色最终目录下的 `index.md` 只保存角色页基础字段；原作经历、原作关系分别写入 `original/experience.md` 与 `original/relationships.md`，并生成空的 `original/state.md`。本轮不生成角色知识；其他实体类别没有角色子文件。

### 用户归类（实体型）

全部分块提取完成后流水线暂停，列出每个实体型类别的实体文件夹。程序依据各实体的别称标出疑似同一实体的候选；用户勾选两个以上文件夹表示它们是同一实体，防止别名、昵称被当作新实体。用户确认归类后流水线才继续。归类可跳过，跳过时每个文件夹作为独立实体。

### 模型整合

- 实体型：对每个实体（或用户归类后的实体组），模型读取其文件夹内全部文件，去重整合为终稿。
- 文档型：文风与世界观由模型读取该类别文件夹内全部分块分析稿，整合为终稿；写作手法只按块保存，不调用跨块正文整合模型。
- 逐条收录：不整合。
- 角色：主文件只含基本人设（外貌、性格、能力等），不涉及剧情；经历与人际关系分别存于子文件夹，按分块顺序整理成时间线，保留各段 P 引用，不做去重合并。
- 整合调用的输入只含对应文件夹内容，同样经模板校验与两次失败上报。

### 模板

以下四个新增模板的字段均非必填，无对应信息留空；“参考片段”统一用 P 编号引用原文，由程序还原为原文片段。

| 模板 | 字段 |
|---|---|
| 写作手法 | 手法名称、类型（叙事 / 描写 / 对话 / 结构 / 节奏等）、手法说明、适用场景、实现要点、效果、参考片段 |
| 素材特点 | 名称、所在位置（分块与章节）、类型（剧情安排 / 表现形式）、安排描述、效果、参考片段 |
| 角色经历 | 时间顺序（分块与章节）、阶段名称、经历描述、对角色的影响、参考片段 |
| 角色人际关系 | 关联角色、关系类型、关系描述、变化节点（分块与章节及变化内容）、参考片段 |

角色、势力、物品、地点、特殊规则、文风、世界观沿用现有八类原创设计的模板与“不涉及剧情”规则。写作手法与素材特点同在 `lorebook/note/`，以元数据中的类型区分。

### 写作手法与写作素材的检索索引

- 提取后由 AI 阅读各成功条目的完整模板字段，为每个条目生成分类、简短摘要和检索词，不合并、不删减或重写条目正文。
- 条目较多时分批阅读，程序汇成两份总索引；每批输出必须覆盖全部输入条目，遗漏、重复和未知条目均视为校验失败。索引单元失败可单独重试。
- 确认写入时，写作手法保存到 `lorebook/note/写作手法/<名称>/index.md`，素材特点保存到 `lorebook/note/写作素材/<名称>/index.md`；两个入口文件位于 `lorebook/note/写作手法索引.md` 与 `lorebook/note/写作素材索引.md`。
- 索引按分类列出标题、摘要、检索词、来源分块与真实项目路径，供 AI 先读索引再按路径读取需要的文档。程序根据实际成功写入的目录生成 Markdown 链接，AI 不生成路径。
- 取消勾选、删除、跳过、冲突待定或写入失败的条目不进入发布索引。另存为指向新目录；后续任务追加同类索引，保留已有任务的条目；同一路径只保留一条记录。再次确认时移除指向已不存在文件的旧索引项。
- 审阅期正文编辑或手动合并使对应 AI 检索注释失效，确认写入前补生成。旧任务没有 AI 索引时也在确认写入前生成。索引生成失败时不开始本批正文写入。
- 发布索引写入失败时报告具体索引文件，保留已经成功写入的条目台账，再次确认可补写索引。索引同名文件不是可识别的生成索引时拒绝自动覆盖。
- 既有已经保存到 note 根目录的条目保持原路径，不自动移动用户文件；本行为适用于新写入的提取条目。索引是普通 Markdown 文件，可由现有文件读取工具读取；不改变写作助手的自动素材选择策略。

### 审阅与写入

整合或索引完成后，用户在审阅清单中看到全部待写入条目，默认全选；写作手法按块草稿逐条进入清单，可编辑、删除、拆分误合并的条目，或勾选几条手动合并。手动合并会发起一次模型合并调用。确认后一次性批量写入 `lorebook/` 对应目录。

待写入条目与已有素材同名时进入对比确认，可选覆盖、另存或跳过，未确认前不写入。Agent 可代用户批量确认新条目的写入；覆盖用户设计的条目必须由用户本人确认。

### 来源标记

所有 `lorebook/` 素材在元数据中标记来源 `origin: design | extract`；缺失视为 `design`，旧素材无需迁移。提取素材另带来源文件、内容哈希与 P 段落引用。

## 状态与转换

任务状态：运行中 → 待归类 → 整合中 → 待审阅 → 已写入；任一阶段可进入 已取消 / 已中断。

| 事件 | 结果 | 约束与幂等 |
|---|---|---|
| 开始任务 | 创建任务与中间产物目录 | 同一来源同一时刻只有一个运行中的素材任务 |
| 一个发现、逐角色或“块 × 类别”单元完成 | 产出写入中间产物 | 完成的单元重复执行不产生重复片段 |
| 单元连续失败两次 | 标记失败并上报，其余继续 | 可由用户或 Agent 单独重试该单元 |
| 全部分块完成 | 进入待归类（无实体型类别则跳过） | |
| 用户确认归类 | 进入整合 | |
| 整合完成 | 进入待审阅 | 失败的整合单元可单独重试 |
| 用户确认写入 | 批量写入并记录 | 部分写入失败时说明失败项，已成功项不回滚也不重复写 |
| 取消或中断 | 已产生的中间产物保留 | 可继续未完成单元 |
| 重新提取 | 覆盖同来源旧中间产物前需确认 | 中间产物保留至用户手动清理或被重提覆盖 |

## 副作用与数据

- 中间产物与任务状态在 `.nbook/inspiration/extractions/<任务 ID>/`，属于项目内部状态，项目关闭后可恢复，由用户手动清理或被重提覆盖。
- 终稿写入 `lorebook/` 必须经现有 tracked workspace writes 与项目 mutation gate，进入工作区历史，不建立旁路写入。
- 流水线内每次模型调用（逐块提取、实体与文档整合、索引注释、手动合并、修复重试）的思考能力固定关闭，由流水线设置，不受工作台思考开关影响；输出质量由模板校验与修复重试保证。
- 来源保持只读。

## 失败与恢复

- 单元失败、模型超时、配置缺失、项目关闭、来源哈希变化都不使任务静默成功；已完成单元与中间产物保留。
- 审阅写入前不得修改 `lorebook/`；对比确认的任何一项被拒绝时，该项保持原文件不变。
- 子文件夹能否作为 `lorebook/` 内容节点被索引：已核实可行（见“实现合同”）；若今后不能，则角色经历与人际关系的最终形态以保持“主文件只含基本人设、经历与关系分开存放”为准，并在 Task 内报告取舍，不改变本节行为。

## 边界与兼容

- 取代 [inspiration.workbench](../ui/inspiration-workbench.md) 首版的“作品分析提取”：不再提取大纲和细纲，类别调整为本 Spec 的九类。原创设计的八类专业方向与保存行为不变。
- `lorebook/` 的目录约定见 `assets/reference/content/lorebook.md`；本能力不新增顶级目录。
- 来源标记字段是对内容节点元数据的增量扩展，缺失即视为用户设计，旧文件无需迁移。
- 真实模型调用、数据库迁移和发布需另行授权，本 Spec 不构成授权。
- **实施范围**：实现本能力时只做本 Spec 及其 Task 规定的内容。实施中发现的其他模块问题不顺手修复，完成后集中报告；仅当该问题阻碍本能力开发时才处理，并在报告中单独说明。

## 验收与 Smoke

- Given 约 12 万字来源，Then 切为约三个分块，P 编号与来源一致；角色先对每块发起一次名单发现，再对每个角色在其出现块逐个发起调用，其他八类每块各发起一次独立调用，提示词前缀均为对应块原文。
- Given 第 2 块中角色“小明”以别称出现，且已知名单含“明”，When 模型返回标准名称，Then 追加到已有角色文件夹而非新建。
- Given 文风调用，Then 已知实体名单不出现在其上下文中。
- Given 某单元产出引用越出本块，Then 带错误信息重试；再失败则标记失败并上报，其他单元继续。
- Given 全部分块完成，Then 流水线暂停并列出实体文件夹，疑似同一实体的候选已标出；用户勾选两个文件夹为同一实体后，整合时合并为一个条目。
- Given 角色整合完成，Then 主文件只含基本人设，另有按时间顺序的经历与人际关系，且均带 P 引用、未被去重。
- Given 素材特点，Then 每条一个文件，含所在位置与参考片段，且不做同名合并。
- Given 两类 note 素材提取完成并确认写入，Then 正文分别落在写作手法与写作素材目录，note 根下两份索引包含 AI 摘要、分类、检索词和存在的文档链接，未写入条目不进入索引。
- Given 多次确认、另存为或后续任务写入，Then 索引保留已有路径并追加或更新真实成功路径，不重复调用已缓存且正文未改变的索引注释；索引写入失败不丢失正文写入台账。
- Given 审阅清单，Then 默认全选，用户取消勾选的条目不写入；确认后条目出现在对应 `lorebook/` 目录，元数据 `origin: extract` 且带来源文件、哈希和 P 引用。
- Given 待写入条目与用户设计的条目同名，Then 进入对比确认，Agent 不能代为覆盖；用户选择“另存”后原条目不变。
- Given 任务运行中关闭项目再打开，Then 任务显示为已中断，已完成单元的中间产物保留，可继续。
- Given 任意素材提取模型调用，Then 请求的思考能力为关闭，不随工作台思考开关变化。
- Given 同时运行一个大纲提取任务与一个素材提取任务，Then 两者状态与进度互不影响。

## 实现合同

以下是已落地部分的事实描述：来源标记与模板、素材提取流水线、HTTP 路由与 Agent 工具、“作品提取”界面。

### 来源标记

- `lorebook/` 内容节点 frontmatter 增加可选顶层字段 `origin: design | extract` 与 `extraction`；缺失 `origin` 读作 `design`（`readWorkspaceContentOrigin`），旧文件不迁移，解析与序列化的字节结果不变。
- `extraction` 为 `{sourcePath, sha256, citations}`：`sourcePath` 沿用来源路径格式，`sha256` 为 64 位小写十六进制，`citations` 为 1 到 500 个 `{firstParagraphId, lastParagraphId}`，编号格式 `P` 加正整数。
- schema 要求 `origin: extract` 必须带 `extraction`，反之 `extraction` 只能出现在 `origin: extract` 的节点上。
- 落点：`shared/dto/inspiration-material.dto.ts`（合同）、`server/workspace-files/content-node-schema.ts`（frontmatter schema）、`server/inspiration/material-template.ts`（`buildExtractedMaterialFrontmatter`）。

### 九类与例外开关

`MATERIAL_CATEGORIES` 登记九类素材的目录、处理模式与 `allowsPlotDevelopment`；只有写作手法与素材特点为 `true`，其余类别仍遵守“不涉及剧情”。该规则原先只存在于 Inspiration Profile 提示词文本，没有代码校验；本合同提供程序可读的开关，流水线只在提示词层面取舍（见“素材提取流水线”）。

### 四个新模板

| 模板 | 位置 | 元数据 |
|---|---|---|
| 写作手法 | `lorebook/note/写作手法/<名称>/index.md` | `type: note`，`subtype: writing-technique` |
| 素材特点 | `lorebook/note/写作素材/<名称>/index.md` | `type: note`，`subtype: material-feature` |
| 角色经历 | `lorebook/character/<stable-id>/original/experience.md` | `type: character`，`subtype: experience` |
| 角色人际关系 | `lorebook/character/<stable-id>/original/relationships.md` | `type: character`，`subtype: relationship` |

- 字段与顺序与“模板”表一致，全部非必填；空白值被丢弃，整条记录至少要有一个非空字段。
- `validateMaterialTemplateFields` 校验：字段归属（错误信息指出字段属于哪个模板）、值必须为文本、素材特点的“类型”只接受“剧情安排”或“表现形式”、“参考片段”的 P 编号格式（`P12`、`P12-P15`，以空白、逗号、顿号分隔）、结束编号不小于起始编号；提供来源段落列表时引用必须存在，提供分块范围时引用不得越界。错误消息为中文，可直接拼入修复重试提示词。
- `restoreParagraphReferences` 按段落列表把 P 引用还原为原文片段；引用缺失或顺序颠倒时抛错，不返回残缺片段。`renderMaterialBody` 渲染正文，传入段落列表时“参考片段”展开为原文引用。角色经历与人际关系为多条记录，按传入顺序渲染，不去重合并。

### `lorebook/character/<stable-id>/` 子文件夹

已核实可行，无需替代形态。角色稳定 ID 目录下的 `index.md` 是基础资料，`original/` 与 `plans/<plan-id>/` 存放侧面资料；`scanWorkspaceTree` 与 `createWorkspaceContentIssues`（项目文件索引共用）对嵌套递归处理。角色管理服务按固定文件名读取这些侧面，不把旧的 `character/` 路径或旧的 `experience/index.md` 结构作为兼容入口。

### 已知限制

- 工作区 UI 的 lorebook 详情面板（`WorkspaceLorebookDetailPanel.vue`）原先保存时会丢弃 `origin`、`extraction` 与 `ext`；已修复为保存时原样写回，编辑提取素材不会丢失来源标记。

### 共用任务框架

素材提取使用与大纲提取相同的后台任务框架（任务记录、单元、调度、取消／继续／单元重试、唯一性、来源复核、校验重试、进度），事实描述见 [outline-extraction.md 的“共用后台任务框架”](outline-extraction.md#共用后台任务框架)。素材流水线的接入点：`kind: "material"`；角色发现、逐角色和其他块 × 类别单元分别持久化，全部完成后 `settle` 返回 `awaiting-input` 等待用户归类，输入经 `acceptInput` 与 `manager.provideInput` 提供；之后 `settle` 返回 `continue` 动态追加整合单元。同一块不同类别的提示词使用逐字节相同的前缀。

### 素材提取流水线

- 角色发现单元按块建立；逐角色单元按候选角色和出现块建立。其他类别单元仍为“块 × 类别”，按块顺序、块内按规范类别顺序。已知实体名单只追加在实体类调用的原文之后；文风、世界观、写作手法、素材特点的调用不带名单。字段校验用 `validateMaterialTemplateFields`，参考片段必须落在本块范围内；失败走共用框架的一次修复重试，仍失败则该单元失败，其余继续。
- “不涉及剧情”（写作手法与素材特点除外）只在提示词里约束，没有程序校验。
- 中间产物在 `.nbook/inspiration/extractions/<任务 ID>/`：`entities/<类别>/<实体>/block-NNN.json`、角色另有 `experience/`、`relationship/` 子目录，`documents/<类别>/block-NNN.json`，`features/block-NNN-<序号>.json`，整合产出在 `integrated/`，待写入清单在 `review.json`。单元重复执行整体覆盖本块产物，不留重复片段。
- 全部提取完成后，有实体文件夹则任务为 `awaiting-input`（待归类），没有则直接整合。归类输入是 `{skip: true}` 或 `{groups: [{category, folders}]}`，只允许同类别文件夹、每个文件夹至多一组。疑似同一实体只按名称或别称重合标记，不自动合并。
- 后处理单元：每个实体（或归类组）一个，文风与世界观各一个整合单元；写作手法和素材特点各一个索引单元，正文不整合。`material-note-index.ts` 逐批读取完整字段（每批最多 24 条，以 48,000 字符目标拆批，单条保持完整），AI 只返回 `group`（最多32字）、`summary`（最多160字）、`keywords`（1到5项，每项最多24字），以内容哈希绑定条目，严格校验全部输入身份均被覆盖。写作手法另外保留按块号升序的路径、标题、P 引用定位表。其他整合输入只含对应文件夹内容；产出的参考片段不得超出草稿已有范围；只有一份草稿时不调用模型。角色主文件只含基本人设，经历与人际关系按块顺序保留 P 引用，不去重。
- `material-note-index-write.ts` 发布 note 根下的两份 Markdown 索引；frontmatter `subtype: material-index`、`ext.materialIndex` 保存版本、类别及已发布条目注册表，正文按分类渲染摘要、检索词、来源及链接。写入经项目 mutation gate 与 tracked workspace writes；`WriteReport.indexPaths` 返回实际更新的索引路径，索引失败以 `outcomes` 中 `index:<category>` 失败项报告。界面与 Agent 确认写入均提供项目生命周期信号，正文变更需要补生成时保持模型与思考合同一致。
- 审阅与写入在任务之后独立进行（任务状态集合没有“审阅中”）：整合结果转成待写入清单（纯数据，默认全选，支持编辑、删除、拆分、手动合并，手动合并一次模型调用）。确认写入经项目 mutation gate 与记账写入落到 `lorebook/<类别目录>/<名称>/index.md`；角色使用稳定 ID 作为目录名，原作经历写入 `original/experience.md`、原作关系写入 `original/relationships.md`，并生成空的 `original/state.md`，主文件 `id` 与目录稳定 ID一致。frontmatter 为 `origin: extract` 加来源标记。确认前不写 `lorebook/`。
- 同路径且内容不同视为同名冲突，必须逐条决定覆盖、另存为（默认“<名>（提取）”，原条目不动）或跳过；内容逐字相同视为已写入。Agent 确认不能覆盖 `origin` 缺失或为 `design` 的条目；对 `origin: extract` 的旧提取条目允许覆盖，用户本人可覆盖任意条目。部分写入失败时逐条报告，成功的节点不回滚也不重复写，重新确认只补写缺失节点。
- 实现位于 `packages/neuro-book/server/inspiration/extraction/material-*.ts`；使用方需先调用 `registerMaterialExtractionPipeline()`。
- **路由与 Agent 工具**：路由位于 `packages/neuro-book/server/api/inspiration/extraction/`，请求与响应 schema 在 `shared/dto/inspiration-extraction-api.dto.ts`，任务控制路由与大纲提取共用，见 [outline-extraction.md 的“路由”](outline-extraction.md#实现合同)。素材专属：
  - `POST /tasks`（`kind: "material"`，来源与可选类别，缺省全部九类）；`POST /tasks/{id}/input` 对素材任务只接受 `{skip, groups}` 归类输入。
  - `GET /tasks/{id}/material/classification`：归类列表与疑似同一实体候选。`GET /tasks/{id}/material/review`：待写入审阅清单。`POST /tasks/{id}/material/review/action`：`select`、`update`、`remove`、`split`、`merge` 之一，返回更新后的清单，合并经一次模型调用。`GET /tasks/{id}/material/review/conflicts`：同名冲突与新旧对比。`POST /tasks/{id}/material/confirm-write`：可带逐条 `decisions`（覆盖、另存为、跳过），返回写入报告。
  - 确认者身份由服务端按调用来源填入：界面路由固定为 `{kind: "user"}`，请求体里没有也不接受 `confirmer`（strict 校验 400）；Agent 工具使用 `{kind: "agent", sessionId}`，会话 ID 来自工具上下文。
  - Agent 工具在 `server/agent/tools/extraction-tools.ts`，共四个：`start_inspiration_extraction`、`get_inspiration_extraction_progress`、`confirm_inspiration_material_write`、`get_inspiration_extraction_failures`；只下发任务、查询进度、确认新条目写入、读取失败报告。确认写入不带 decisions，因此只写无冲突的新条目，冲突原样返回并交给用户在界面里决定，不能覆盖 `origin` 缺失或为 `design` 的条目；不勾选、不编辑审阅清单，不处理归类。工具未绑定任何 Profile。
  - **界面**：入口、组件位置、服务调用与轮询规则同 [outline-extraction.md 的“界面”](outline-extraction.md#实现合同)；素材提取与大纲提取是“作品提取”页里并列的两个入口，各有独立任务与进度。素材提取需要先选来源并成功载入分块预览（用它的来源哈希启动任务）。
  - 类别默认勾选九类，启动时按规范顺序提交；全部取消则不能开始。
  - 任务等待输入时显示待归类列表：同类别的文件夹勾选后合并成组，疑似同一实体的候选只标注并提供“选中这几项”，不自动合并，可以整体跳过；跨类别不能合并。提交后显示整合进度，沿用同一进度面板（逐单元状态、失败重试／跳过、取消／继续）。
  - 任务结束后显示待写入清单：默认全选，可全选、全不选、逐项选择，编辑（标题、别称、节点正文）、删除、合并（同类别至少两项）、拆分（仅角色，把经历与人际关系移到新条目）；每次操作后以服务端返回的清单为准。已写入的条目只读。
  - 点击“确认写入”先读取同名冲突：无冲突直接写入；有冲突显示逐条新旧对比，选择覆盖、另存为（必须填名称）或跳过，默认跳过，现有文件不允许覆盖时不提供覆盖选项；表态后才写入。写入后显示报告，失败项显示服务端给出的原因，可以再次确认写入。
  - 界面请求不携带确认者；错误一律显示服务端的中文消息，缺失时按业务码给通用说明。未启动时显示块芯片，支持全选、清空、反选、点击切换和 Shift 连选；显示基础调用量，启动后选择锁定。跳过前序块时提示可能影响后续实体识别；清空块或类别不能启动。
