# 三模块统一提示词管理

状态：accepted。2026-10-04，开发者已审阅并测试配置中心 Demo，接受整体设计，新增“内置默认不可修改或删除”约束并授权正式实装。当前行为与验收依据见 [全局提示词管理 Spec](../specs/ui/prompt-management.md)。

## 问题

设计工作台、大纲规划工作台、写作模块的提示词分散在 Agent Profile、流程函数和动态拼接代码中。用户无法在一个入口管理全部模型调用，也无法统一配置带 system/user/assistant 角色的前置消息。

## 目标与非目标

统一管理上述三个模块全部模型调用使用的提示词，包括 Agent、专家和流程直接调用。设计工作台中的作品大纲与素材提取、角色发现与逐角色提取、笔记索引和模型修复步骤均纳入范围。

预输入提示词是正常交互之前的有序消息序列，包含 system、user、assistant；assistant 是预置回复，并非本次模型实际生成的结果。真实接口使用独立 system 字段时，由适配器处理，并展示实际发送结构。

首轮先保存设计并制作 UI Demo；评审后正式接入配置中心、全局持久化和三个模块的模型调用。暂不设计项目级覆盖。提示词编辑不改变工具权限、输出 schema、校验或写入流程。

## 已确认方案

### 作用域与版本

配置作用于所有作品，仅提供全局配置。创建新会话时固定当时的提示词版本；已有聊天记录继续使用原版本，包括继续交流、追问和后续专家调用。修改配置仅对新开聊天记录生效，不在旧会话下一条消息时自动更新。

无聊天记录的流程以任务为版本边界：新建提取任务固定版本，重试、恢复和后续阶段沿用。持久化可恢复的完整模板及静态依赖快照，而不只是版本号。一次性大纲方向生成和审查以该次请求为边界。此规则随 Demo 整体设计获准实装。

### 入口与窗口

入口为配置中心 → 全局 → 提示词管理。保持现有配置中心视觉与导航结构。窗口占据屏幕约三分之二，宽高各约 82%，即面积约 67%；窄屏按现有窗口控件收敛。开发者已接受 Demo 的窗口比例。

### 调用用途与预设列表

按设计工作台、大纲规划工作台、写作模块分类，以列表展示所有调用用途，每项标注名称与作用。提示词绑定调用用途，不绑定 Provider 的某个模型名称；切换模型仍可使用相同预设。

每项包含预设下拉列表，旁边依次提供删除、新建、编辑三个按钮。选择预设决定后续新会话使用的版本；新建或编辑进入该调用用途的提示词条目列表。默认展示实际内置提示词及明确动态变量。内置预设的“编辑”显示为“查看”，用户必须新建副本后才能编辑。

### 提示词编辑

编辑区右上角提供新建条目按钮。每个条目头部从左到右依次为：鼠标左键拖动排序手柄、名称、角色下拉（system/user/assistant）、删除按钮。点击条目展开正文输入框，默认显示已设置的提示词；输入框下方右下角为保存按钮。

未点击保存前，编辑均为草稿，不生效、不持久化；离开当前页面时丢弃草稿，恢复已保存内容。排序决定消息序列中的位置，role 决定实际发送角色，不能仅改变 UI 标签。

### 已接受的编辑细节

- 使用列表页和同区域编辑页，编辑页保留返回列表入口，避免在配置中心中继续叠窗口。
- 新预设从当前预设复制，保存前只是草稿；名称在编辑页修改。
- 条目正文下的保存提交当前预设全部草稿（正文、名称、角色、顺序、新增和删除）为一个一致版本；底部另提供同义的“保存预设”，保证最后一条删除后仍可保存。
- 删除自定义预设使用内联确认。内置默认永久保留，不可删除、修改正文或角色、改名、排序、新增或删除条目；界面及服务端同时保护。删除当前自定义后回到内置，历史快照保留。
- 多个条目可同时展开；正文与长列表在内容区滚动，导航、页标题和保存区保留可达。
- 原 Demo 保存仅更新内存；正式模块保存到 App State，与小说项目隔离，刷新或应用重启后恢复。

## 备选方案与取舍

未采用直接在通用 Agent 配置页添加一个系统文本框：它无法覆盖非 Agent 流程和前置 assistant/user 消息。首版采用用户指定的分类列表和预设编辑形式，不制作无关的多套布局变体。

逐条保存与整个预设保存各有取舍：逐条保存直观，但排序、删除和新预设创建仍需要独立提交边界；整体提交可以保留一致的消息序列。开发者接受 Demo 后，正式实现沿用整体提交。

## 数据、接口、迁移与回滚影响

正式实现使用稳定的调用用途 ID、预设 ID、消息 ID、角色、名称、正文、顺序和不可变版本。动态变量由用途声明，未知或缺少必需变量明确拒绝保存。2026-10-04 后续优化要求新配置逐条保留三种角色与完整顺序，OpenAI Chat Completions / Responses 使用原生消息列表；既有快照保持原 system 合并方式。不支持交错系统消息的接口明确拒绝该结构。旧会话没有绑定时固定内置基线，旧提取任务沿用原默认路径；均不读取当前自定义方案。

原文、人设、章节和场景等动态数据仍由业务流程提供；用户编辑的是模板及前置消息，不把当前小说正文保存成全局默认。导入的静态指南等实际进入模型的提示内容也应可见并提供编辑或覆盖入口。

本轮不调用真实模型、不做部署或远端操作。正式预设删除不能删除仍被历史会话引用的版本；恢复内置配置也不得改写历史版本。方案缺失或快照损坏时明确失败，不静默切换版本。

## 对 Spec 的预期改动与验收

统一提示词管理 capability 已登记在 Spec。验收包括：三类角色和排序实际进入模型请求；预设覆盖每个调用用途；内置仅能查看复制；未保存退出丢弃；新会话采用新版本而旧会话及子 Agent 保持旧版本；恢复历史不依赖当前预设存在；长内容和窄屏控件可达。

首轮 Demo 的证据仅覆盖内存交互与布局。正式实装另以服务端持久化测试、真实 Faux Provider 请求、任务重试回归和正式组件隔离浏览器走查验证；真实模型质量由开发者后续测试。
