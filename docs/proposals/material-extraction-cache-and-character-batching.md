# 角色分组提取与缓存友好请求

## 背景

角色发现后，旧流程会为“角色 × 出现分块”各发起一次完整提取请求。长篇作品中的角色候选很多时，同一分块原文会被重复发送，既增加请求数量，也降低 DeepSeek 前缀缓存的利用率。日志只能看到统一的 `error`，无法把失败、角色组和缓存用量对应起来，排查成本也随之升高。

## 当前行为与证据

当前流水线已经先按分块发现角色，再为候选角色建立提取单元；同一分块的角色请求仍需要明确固定前缀和分组边界，才能保证这项调度不会因为排序或提示词配置变化而破坏恢复。现有 Mock 回归可以观察到角色候选、分块和产物路径，但真实 Provider 的缓存读写只有在响应 usage 提供对应字段时才可确认。历史日志中 `error` 响应缺少稳定的任务单元关联，因此本提案把关联字段和前缀指纹列为实现合同。

## 角色分组合同

发现阶段至少保存角色名称、别名和出现分块；角色等级由程序根据覆盖率计算，名称或别名命中次数只作为发现阶段的辅助信息，不进入最终角色文件。

- **A 级（高频）**：覆盖率达到 40% 或覆盖至少 8 个已选分块。每个分块单独提取。
- **B 级（中频）**：不满足 A 级且覆盖 3 至 7 个分块。同一分块内最多两人一组。
- **C 级（低频）**：覆盖 1 至 2 个分块。同一分块内最多三人一组。

分组先按分块，再按等级和稳定的 `folderKey` 排序，不能跨分块、跨等级合并。任务单元记录 `block`、`tier`、候选稳定键和角色名称，单元 ID 由这些稳定值确定，恢复和重试不得因为排序变化而产生重复单元。

一次分组请求返回多个角色时，输出仍必须逐角色包含完整模板。程序按角色独立校验、独立写入 `entities/character/<folderKey>/` 的基础片段、经历片段和关系片段；不会把多个角色合并成一个文件。没有可提取信息的角色仍需返回空字段，以便程序确认该角色已处理。

分组校验必须确认：返回角色集合与请求集合完全一致、没有重复或未请求角色、每条引用都在当前分块范围内、每个角色的字段和子节点分别符合模板。分组请求失败时先进行一次分组修复；修复仍失败时，后续重试应能按角色拆成单人单元，避免一个角色的问题阻塞同组其他角色。已成功写入的角色不得重复写入。

## DeepSeek 缓存顺序合同

角色提取请求保持如下顺序：

```text
系统信息 → 当前分块原文 → 角色字段模板 → 动态角色名单、别名与范围 → 提取目标与任务要求 → 修复信息
```

系统信息和同一分块的原文、模板必须逐字节稳定。动态角色名单、分块范围、任务要求和修复信息位于后部；修复信息只能追加，不能插入或改写前缀。消息角色、换行和 JSON 字段顺序同样属于缓存前缀合同。托管提示词有配置示例时，也必须保留系统消息在前、原文在动态任务之前的顺序。

本轮不假定 Provider 一定会命中缓存，也不改写 Provider 的缓存协议；程序先保证请求前缀稳定并记录可按任务、单元和角色组关联的观测数据。真实缓存命中率留待真实模型验收。

## 可观测性

每次提取模型调用记录任务 ID、单元 ID、用途、分块、角色组、等级、Provider、模型、停止原因、输入输出 token、缓存读写 token、最大输出、输出长度和稳定前缀哈希。日志不写入原文、完整提示词或密钥；缓存字段缺失时记录为 `null`，不能伪造命中数据。统计字段使用明确的非敏感字段名，仍保持 API key 等秘密字段脱敏。

## 数据、接口与恢复影响

任务单元继续使用现有 `ExtractionUnit`，仅在 `data` 中保存 `block`、`tier`、`folderKeys` 和角色显示名；角色文件仍按角色目录及分块片段独立保存，不改变已确认的中间产物结构。模型请求的 `metadata` 只携带任务、单元、用途和统计关联字段，不携带原文或密钥。旧任务恢复时保留旧单元 ID 与提示词快照；新分组用途缺少于旧快照时沿用流程内置提示词，避免历史任务被当前配置阻断。

分组失败后的单角色回退通过追加独立任务单元实现，可能增加该组本次请求数。集合完整的输出先逐角色校验并保存成功项，仅失败角色补排；集合错误先整组修复一次，仍失败再补排全部角色。后续重试只处理失败的单人单元。空资料角色不创建空档案。网络错误不触发拆组；取消、来源哈希变化和模型配置错误仍由现有任务框架处理，不改变失败语义。

## 预期请求量

设某分块有 `A` 个高频、`B` 个中频和 `C` 个低频角色，旧方案约产生 `A+B+C` 次角色调用；新方案为 `A+ceil(B/2)+ceil(C/3)` 次，发现阶段仍为每个分块一次。回退只在分组校验或模型调用失败时发生，因此该数值是成功路径的上限目标，而不是对异常路径的保证。

## 对 Spec 的预期改动

更新 `inspiration.material-extraction` 的 planned 合同：增加角色发现的覆盖率分级、同块分组、逐角色校验写入、拆分回退、缓存前缀顺序和可观测字段；不改变归类暂停、审阅后写入 `lorebook/` 以及思考关闭等既有合同。

## 验收

- 同一分块的 A 级角色各有一个单人单元，B 级按两人分组，C 级按三人分组；任何组都不跨分块。
- 分组请求的公共前缀哈希相同，动态角色名称不出现在该哈希覆盖的前缀中，修复文本位于请求末尾。
- 分组输出中的每个角色分别写入自己的中间文件；一个角色失败时错误信息能定位到角色，重试不会重复已成功角色的片段。
- 提取日志可以按 `taskId` 和 `unitId` 关联 stop、length、error 以及缓存 token 字段，且不泄漏秘密或完整正文。
- Mock 回归覆盖等级边界、分组边界、输出缺失/重复/越界引用、幂等写入和日志字段；真实模型与真实缓存命中率不在本轮验收。

## 决策记录

- 2026-10-08：开发者接受“稳定前缀 + 按覆盖率分级并在同一分块内分组”的方案；高频角色单独提取，中频两人一组，低频三人一组。先完成 Mock 回归和日志可观测性，真实 DeepSeek 缓存命中率另行验收。
