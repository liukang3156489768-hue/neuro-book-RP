# Inspiration 设计模块落地

状态：accepted。开发者已于 2026-09-20 明确要求按《设计模块计划》开始开发，并在首版建议与本地开发例外说明后回复“批准”；随后明确要求将作品来源改为真实分析和提取，并提供聊天上下文及聊天记录管理。

## 问题

项目已有分类素材、Agent 运行时和文件工作区，但缺少集中承载灵感设计、成果审阅与作品资料提取的页面。用户需要在保持编辑工作区可见的情况下设计可复用素材。

## 目标与非目标

目标为原计划中的八类原创设计和作品提取。原创内容必须先展示具体成果，经用户确认后保存到当前项目的对应素材目录。提取时来源保持只读，引用必须能定位原文。每个项目的聊天记录保存为内部可归档状态，恢复窗口后仍可查看用户指令、分析范围及关联成果。

本次不调整 writer.pro 输入，不将全部素材自动注入其他 Agent，不修改开发者原始计划文档。

## 当前行为与证据

- `packages/neuro-book/app/utils/workbench-chrome.ts` 定义左侧入口、项目可用性和用户资产模式下的禁用规则。
- `packages/neuro-book/app/components/novel-ide/NovelIdeActivityBar.vue` 根据入口定义发出事件；页面宿主负责打开功能窗口。
- `packages/neuro-book/app/components/common/DialogWindow.vue` 提供可拖动的非模态窗口。主工作区已有未提交的窗口尺寸与响应式改动，实施时须保护并记录集成依赖。
- 服务端 `server/workspace-files` 与 `server/workspace-history` 拥有项目路径、文件变更、索引和历史，设计模块不另建直接写文件旁路。

## 方案、备选方案和取舍

确定采用左侧“设计模块”入口，打开 Inspiration 悬浮窗口；没有可用作品或位于用户资产工作区时禁用。窗口沿用项目主题，关闭窗口与切换项目必须明确区分，防止旧项目结果进入新项目。

原创流程复用现有 Agent 执行能力，Inspiration 组织需求及八类专业设计。素材正文先展示供编辑和反馈，明确确认后由程序保存；模型本身不拥有越过审阅直接写正式素材的权限。

提取处理采用程序负责切分编号、引用解析、文件保存，模型负责分析和整合的职责划分。不得用模型补写替代失效引用。模型一次只接收用户选择的分块，结果逐项带 P 段落范围及源文件哈希；类别或引用越界时拒绝该次结果。主线大纲与细纲先以 `note` 类“写作指导与参考资料”保存，避免在未设计大纲库合同前伪造数据库实体。

本次采用的交付节奏与备选方案：

1. 已采用：窗口、八类原创设计审阅保存、会话持久化、来源选择与切分编号，以及按选中分块的真实提取。
2. 未采用：自动跨块实体合并、将提取结果直接写入大纲数据库；这两项仍需各自的数据合同。

## 数据、接口、安全、迁移、发布与回滚影响

采用当前项目身份与既有工作区写入边界；来源作品只读。文件名、草稿存储、同名冲突、重复提取与大纲库关联仍需按本次获批范围补齐合同。不得修改已有素材来回避命名冲突。模型失败、取消、项目关闭与保存失败必须保留可诊断状态。

本地开发不构成真实模型验证、数据库迁移、远端写入或发布授权。新文件格式的兼容及回滚行为在实施前按实际方案补入 Spec。

## 对 Spec 的预期改动

按可独立验收的能力分别登记设计工作台、原创设计审阅保存、作品提取；每项覆盖项目范围、输入、运行状态、失败、取消、持久化副作用与验证。未实现或尚未批准的行为不登记为 implemented。
