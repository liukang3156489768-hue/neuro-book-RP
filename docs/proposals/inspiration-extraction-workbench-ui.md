# Inspiration 作品提取界面优化与旧入口下线

状态：accepted。2026-10-02 开发者确认沿用旧入口的分块预览与选择形式，并逐项决定历史数据、块定义、旧 Profile、验收与本轮范围。本轮采用 A 到 E；实施前将已确认行为同步到相关 Spec，本文不替代当前行为合同。

## 问题

开发者实际使用后观察到：

1. 设计页（“设计与分析”）里仍保留旧的“作品分析与提取”模式，与新的“作品提取”页功能重叠，用户有两个入口、两套结果形态。
2. “作品提取”页只占对话框约三分之二的高度，下半屏空着，划卷表单被压在一块固定高度里。
3. 大纲提取只显示按章节切分的预览，看不到按块（字数）切分的预览与 P 编号范围。
4. 素材提取页完全看不到当前作品的分块与 P 范围，用户无法选择提取哪些块、排除哪些块。旧设计页的提取是可以选块的，新页反而退步。
5. 右键菜单的二级菜单没有贴着父菜单弹出，跑到窗口中部（文件树的“复制路径/引用”“新建”子菜单可复现）。
6. w00020 与此前的 Inspiration 开发中，有一批已记录但按约定暂不处理的问题。

## 目标与非目标

目标：

- 下线旧“作品分析与提取”入口，设计页只保留原创设计；新“作品提取”页成为作品提取的唯一入口。
- 作品提取页铺满对话框，并提供统一的“分块预览”：序号、标题或块名、P 范围、字数。
- 素材提取支持选择块与排除块，并显示预计调用量。
- 大纲提取可看到并选择切分方式（按章节、按字数分块），预览随之变化。
- 修复二级菜单错位。
- 把已记录的问题分类，明确哪些随本方案解决、哪些另开批次处理。

非目标：

- 不重做工作台整体视觉与信息架构；本文只处理上面列出的问题。
- 保持 w00020 已确认的数据去向、确认者与思考关闭规则；本轮新增素材选块，并统一字数模式的分块边界。
- 不做真实模型调用、数据库迁移与发布。
- 不处理写作模块、大纲库内部、工程基础设施问题，只把它们列入待办并给出处理建议。

## 当前行为与证据

以下除特别标注外是读代码得到的事实。第 2 点的“与截图吻合”是推断，没有在浏览器里量过。

1. **旧入口位置**：[`InspirationWorkbenchDialog.vue`](../../packages/neuro-book/app/components/novel-ide/inspiration/InspirationWorkbenchDialog.vue) 的 `mode-switch` 提供“原创设计／作品分析与提取”，`mode === 'extract'` 时右栏显示来源、分块芯片与提取目标。`useInspirationWorkbench.ts` 在 `generate()` 里按 `mode` 调用 `/api/inspiration/extract`，其余调用 `/api/inspiration/generate`。页签名“设计与分析”由 t08 加入。
2. **高度被固定值限制**：对话框是 `100vw × 100dvh`，但 `.extraction-page` 写死 `height: min(760px, calc(100vh - 160px))` 与 `min-height: 460px`，大屏上下方留白，与截图中内容只铺到约三分之二吻合。章节列表另有自己的滚动区，形成嵌套滚动；章节行的 P 范围在窄列里换行（截图 `P10110–` / `P10238`）。
3. **大纲切分方式不可选**：[`structure-service.ts`](../../packages/neuro-book/server/inspiration/extraction/structure-service.ts) 以“识别到章节数是否大于 0”自动决定 `chapters` 或 `chunks`，用户不能切换。`chunks` 模式由 `planChunkChapters`（[`outline-structure.ts`](../../packages/neuro-book/server/inspiration/outline-structure.ts)）把每个段落当单位按约 5 万字分组，不考虑章节边界；而 `source-prepare` 的分块（[`source-split.ts`](../../packages/neuro-book/server/inspiration/source-split.ts)）把完整章节当不可分单位。两处都叫“块”，边界不同。
4. **素材提取没有块选择**：[`material-pipeline.ts`](../../packages/neuro-book/server/inspiration/extraction/material-pipeline.ts) 的 `prepare` 对来源的全部块乘以所选类别生成单元；启动请求 `ExtractionMaterialStartRequestSchema` 只有 `categories`。`MaterialExtractionView.vue` 只知道 `sourceReady` 一个布尔值，没有块数据。数据其实现成：`/api/inspiration/source-prepare` 返回 `chunks`（序号、首尾段落号），旧设计页就是用它画“块 N · P1–P758”芯片。
5. **二级菜单**：菜单由 nb-ui 的 [`ContextMenuPanel.vue`](../../packages/nb-ui/src/components/feedback/ContextMenuPanel.vue) 绘制，各级子面板是 `position: fixed`，却嵌套在带 `backdrop-filter` 的父面板内部。浏览器会把带 `backdrop-filter` 的元素当作 fixed 后代的定位参照，子面板的视口坐标因此被加上偏移。这是可疑原因，但按它推算的位置和两张截图对不上（两张图里偏移几乎相同，约 257 × 271 像素，而父菜单位置不同），所以**根因未确认**，需要先复现。
6. **已记录问题**：见下文“已记录问题清单”。

## 方案

### A. 作品提取页布局与分块预览（建议先做）

- 页面高度跟随对话框：去掉 760 像素上限，页面用 flex 铺满，由内容区自身滚动，不再嵌套滚动。
- 宽屏分为两栏：左栏“分块预览”（来源、切分方式、块列表），右栏“操作与进度”；窄屏（约 900 像素以下）上下堆叠。模型选择与来源选择并入顶部一行。
- 从旧入口抽取共用的“分块预览”组件，迁到作品提取页。按字数分块时沿用开发者截图中的形式：来源选择、段落／章节／分块统计、可换行排列的“块 N · P起始–P结束”芯片；素材页点击芯片切换选中状态，选中与未选中清晰区分，每个芯片内的 P 范围保持单行。复用来源准备数据与原有选块逻辑，补充字数信息；按章节预览时保留章节标题、P 范围与字数。长列表的渲染方式根据实测选择，不预设 64 章必然卡顿。
- 复用既有设计令牌与 nb-ui 组件，新增组件配同名 `.md`，遵循 ui-development 技能。

### B. 素材提取支持选块

- 数据：启动请求新增 `blocks?: number[]`，缺省为全部块；任务参数持久化该列表，恢复与重试沿用，来源哈希校验不变。
- 流水线：`prepare` 只为所选块生成提取单元；整合与审阅只处理所选块产生的片段；进度的块数与单元数按所选块统计。
- 界面：分块芯片支持点击多选，提供全选、清空、反选、按范围选择（如“块 3 到 8”）与 Shift 连选；显示“已选 N 块，基础提取调用 N × 类别数 次”，另说明重试与后续整合会增加调用。启动后选择不可改。
- Agent 工具 `start_inspiration_extraction` 同步增加可选 `blocks`。
- 已知代价：跳过某些块会让“已知实体名单”缺少这些块里首次出现的实体，后续块的归类与整合可能因此少识别同一实体的别名。界面应提示“跳过前面的块可能影响后面块的实体识别”。

### C. 大纲提取显示并选择切分方式

- 预览请求增加切分方式：按章节、按字数分块；按字数时可调目标字数（默认 5 万）。预览列表随之变化，两种方式都显示 P 范围。
- 服务端当前不允许在已识别到章节时强制按块。需放宽：请求带 `mode` 时按请求处理，未带时沿用自动判断。
- 块的定义已确认统一：按字数分块一律使用 `source-split` 的“完整章节为不可分单位”规则，有章节时不切开章节，单章超过目标字数时独立成块，无章节时按完整段落分组；`planChunkChapters` 改为复用它。同一来源、章节边界与目标字数下，大纲和素材的块号及 P 范围一致。这会改 t03 的语义，需要补测试，并同步 Spec。
- 大纲提取本轮始终覆盖整部作品，不增加部分章节提取或排除；素材提取支持选块。划卷与卷纲、总纲汇总继续要求连续完整覆盖。

### D. 下线旧“作品分析与提取”入口

- 界面：移除设计页的模式切换、来源面板、提取目标芯片、`mode === 'extract'` 的分支与相关状态；设计页页签改名为“原创设计”，对话框标题保持。`useInspirationWorkbench.ts` 去掉来源、分块、提取类别相关状态。
- 服务端：移除 `server/api/inspiration/extract.post.ts` 以及 `service.ts` 中的提取路径、`runtime.ts` 的相应注册和 DTO；保留 `sources.get.ts`、`source-prepare.post.ts`（新流水线与新页面在用）、`save.post.ts`、`generate.post.ts`。
- 历史数据：清除旧提取会话与草稿，已保存到 lorebook 的正式条目保留，包括此前的 `note` 类大纲、细纲，不迁移、不删除。现有消息有 `design`／`extract` 类型，会话未固定模式：混合会话只移除旧提取消息与提取草稿，保留原创内容；纯提取会话删除。清理依据消息类型和草稿来源，不仅按会话标题判断。
- Profile：随旧入口一起移除 `inspiration.extract` 的 Profile 源、相关提示词以及旧提取草稿的重新提取调用路径；新流水线不使用这个 Profile。先核实 `.compiled` 的再生机制，再通过现有生成流程更新产物，不手改编译文件。
- 文档与测试：修订 `inspiration.workbench` Spec，去掉首版提取描述中的旧入口与“待开发者决定”；更新 `InspirationWorkbenchDialog` 合同测试与并列 `.md`。
- 顺序：放在 A 到 C 完成并走查之后，避免新页能力不足时旧入口已经没了。

### E. 二级菜单错位

- 先在浏览器里复现并量出子面板的实际定位参照与 `measureCascadePanel` 的输入输出，再确定修法。
- 若确认是 `backdrop-filter` 造成的定位参照，修法是把各级子面板渲染成与父面板并列的节点（同一个宿主下的兄弟元素），而不是嵌套在带滤镜的父面板里。
- nb-ui 的右键菜单、Dropdown、Menubar 共用同一套级联逻辑，修后三处都要回归，并补一个级联位置的测试。
- 这项与其他几项互不依赖，可以最先单独处理。

## 备选方案与取舍

- **旧入口保留一个版本再下线**：风险更低，但用户继续面对两个入口，且旧流程“任一块越界即整体失败”的缺陷还在。你已明确要求取代，所以不采用。
- **素材块选择只做界面过滤、不改服务端**：只能隐藏已生成的结果，不能节省调用，也无法恢复与审计，不采用。
- **大纲与素材各自保留自己的块定义**：改动最小，但同一部作品出现两套块号，用户无法对应，不采用。
- **大纲提取支持排除章节**：见 C，会改变汇总语义，本次不做。

## 数据、接口、安全、迁移、发布与回滚影响

- 接口：素材启动请求与 Agent 工具增加可选 `blocks`；大纲预览与确认请求增加可选切分方式；旧 `extract` 路由删除。均为向后兼容的新增，删除项只影响旧界面。
- 数据：任务文件 `task.json` 增加 `blocks` 字段，缺省视为全部块，旧任务可正常恢复；不涉及数据库迁移。旧入口内部会话与草稿按 D 清理，混合会话保留原创内容；正式 lorebook 条目保留。
- 安全：确认者身份仍由服务端判定，请求不得携带；`blocks` 须校验为存在的块号并去重。
- 发布与回滚：界面与服务端改动按下文顺序分批组织，旧入口下线放在最后一批。代码回滚不能恢复已清除的旧提取会话与草稿；清理过程的中断恢复与失败处理需在实施前写入 Spec。提交、远端写入与发布仍须各自授权。

## 已记录问题清单

按处理方式分类。标“本方案解决”的随上面的改动一起完成；其余另开批次处理。

### 本方案解决

- 旧入口保存的结果与新入口重叠，用户有两个入口（见 D）。
- 素材提取要求先成功载入章节预览才能启动（B 让素材页自己载入分块预览，不再依赖大纲预览）。
- 旧提取“任一块结果越界即整体失败，已完成块的成果丢失”（随旧路由删除消失）。
- 设计页对话框里的大段单行 CSS（旧提取面板删除后随之大幅减少，剩余部分在 D 里顺手整理为多行）。

### 已确认的处理方式

- 分块预览与选择沿用旧入口截图中的形式，迁到新“作品提取”页（见 A、B）。
- 清除旧提取会话与草稿；混合会话保留原创内容，正式 lorebook 条目保留（见 D）。
- 移除 `inspiration.extract` Profile 与相关提示词（见 D）。
- 大纲与素材统一为“完整章节不可分”的块定义（见 C）。
- 大纲仍提取整部作品，素材支持选块（见 B、C）。
- “打开提取方案”本轮维持现状：只打开大纲工作台，由用户手动选择方案。
- 写作助手工具 `read_writing_material` 另开批次支持按 P 段落范围读取，并设置单次体积上限；具体上限与超限反馈在该批次确定，不禁止按需读取原作。
- 本轮做 Mock 回归与浏览器走查，真实模型验收另行安排；两个提取 Spec 暂时保持 `planned`。
- 其他原创设计问题、w00020 实现限制与工程基础设施问题均另开批次核实处理。

### 单独批次处理（与本方案无直接关系）

设计页原创设计流程的既有问题，此前记录较简，实施前需要重新核实：

- 单条候选重新提取（refine）没有取消与超时。
- 追问（ask）复用模板 schema。
- 会话与模式的绑定关系。
- 已保存的草稿仍显示为待审阅。
- `thinkingLevel` 可能为 `undefined`。
- 多个设计 Agent 串行执行。

w00020 的实现限制：

- 章节修正只能撤销最后一项或全部还原。
- 轮询读取失败后不自动重试，由用户刷新。
- 排在长时间“重新汇总”之后的取消，要等汇总结束才生效。

- 使用中的总纲不可删除；孤立总纲级联可能波及其他方案挂载的条目。
- “素材不涉及剧情”规则只存在于提示词，没有代码校验。
- `task.json` 写入不是原子的。
