# 细纲资料补充与独立审核

状态：accepted。2026-10-04 开发者确认模板、按情节读取资料与独立审核，并授权文档保存及实施。

## 问题与目标

细纲简略指明人物、地点、服饰、事件及参考文件，完整资料散落在 lorebook/。仅将姓名和目的传给写手会使外貌、性格、关系与环境依赖模型猜测。资料助手的错误同样会污染正文，因此写作前需要独立审核。

目标：提取、细纲创作、程序解析采用一致模板；资料助手按细纲读取并补充资料；独立审核通过后才调用写手。补充稿只用于本次写作与运行记录，不写回原细纲或修改素材。保留现有正文审阅和主创核对。酒馆导入、宏兼容、Gemini 专用参数不在本轮。

## 助手产出与写手任务模板

```markdown
# 当前场景细纲
【程序保留原细纲的场景要求、地点、角色、服饰、具体情节、描写、写作指导及结束位置】

# 依据细纲补充的资料
## 参与角色
### 角色A
【身份、外貌、性格及其具体表现、必要言行习惯；注明来源】
### 角色B
【同上】
## 本场景涉及的关系与经历
【只提供影响本次互动、当前进度前已发生的资料；注明来源】
## 相关秘密与信息差
【按情节提供；区分写手创作依据与角色实际知道的内容】
## 本场景涉及的环境
【按行动位置展开。始终在教室只给教室；移动到走廊才补充走廊】
## 服饰、物品及其他参考
【展开细纲提及且需要了解的内容】
## 写法参考
【先读索引定位，再读相关文档，提炼适用要点】

# 伏笔执行与必须写到的要素
【程序锁定，伏笔完整作用不交给写手】
# 禁止事项与输出要求
【程序提供；只输出当前场景正文】
```

角色基础资料为参与角色必备补充；其他分类按需求提供，空分类省略。每项补充具有可读的来源定位；短摘录由程序按文件位置获取，概括由独立审核核验。助手不能新增剧情或角色，不能把未来改编计划作为当前事实。关键资料缺失时明确报告，不能凭空补齐。

## 处理与审核流程

1. 程序解析原细纲、保留作者字段，按章准备场景与相关前文。
2. 资料助手识别地点移动、参与角色及互动，按名称或引用定位 lorebook/，读取所需资料，提交逐场景的补充稿及来源。
3. 程序校验场景对应、参与角色覆盖、来源可读性、摘录位置与体积；失败返回资料助手，不调用写手。
4. 独立审核助手在独立会话读取原细纲、补充稿、当前方案与故事进度、相关前文，并可按需核验来源文件。
5. 审核检查原细纲完整性、对象与方案正确性、事实依据、资料充分性与相关性、连续性、信息差和写法适用性。审核不能自行规划或替资料助手改稿。
6. 不通过时返回具体问题，资料助手修订后重新独立审核；有效稿仍需经过原有主创核对及讨论模式下用户确认。
7. 只有通过的补充稿才能交给写手。正文仍经过现有正文审阅与程序校验，通过后写入。

局部改写同样先整理所需资料再独立审核，保持替换范围与用户要求。审核提交非法最多重交三次；资料稿最多被独立审核退回三次，耗尽后明确停止且不写正文。取消、重放与续写由既有 workflow 管理；旧检查点没有本次资料结构时，对未写部分重新补充与审核，已通过场景仍须与原细纲一致。

审核使用独立 Profile 与提示词用途；初始模型沿用助手配置，保持独立会话与工具边界。全部新增模型提示词接入全局提示词管理；既有会话仍保持快照，新会话使用新内置模板或用户预设。

程序记录实际补充来源的内容哈希，在写手调用前及正文写入前核对；来源变化或不可读则停止，不能继续使用已审核的旧摘要写入。局部改写在最终确认替换前同样检查。旧写手自定义模板若没有新增的地点、服饰和补充资料变量，程序将这些事实资料附加为独立任务消息，保留预设原有顺序与角色。

## 验收

- 教室内不移动的场景没有无关校园资料；移动时包含两处必要环境。
- 两个角色的基础资料均有来源，重名、错误路径、缺失角色资料不能进入写手。
- 独立审核退回后先修订再审核；连续退回或非法审核耗尽后无写手调用和正文写入。
- 独立审核通过后保持现有主创核对、场景边界、正文审核、局部替换确认和停止恢复。
