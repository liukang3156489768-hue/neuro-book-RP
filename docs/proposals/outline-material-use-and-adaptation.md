# 大纲规划 Agent 的提取素材运用与改编模式

状态：accepted。2026-10-03 开发者逐项确认下述产品方向，并要求先记录文档再实施。行为合同见 [outline.material-adaptation](../specs/outline/material-adaptation.md)。

## 问题

规划助手与三个专家已能按需读取 lorebook，但缺少对提取角色的基础人设、经历、人际关系的明确运用规则，也没有稳定的笔记发现和筛选流程。改编原作时新增中间章节会造成编号错位；只参考原作而忽略已有改编，会产生动机、关系、状态与事件因果冲突。

## 目标与非目标

- 同时支持保留主要剧情重新演绎、只借鉴结构重设具体剧情两种改编方式。
- 优先补强角色基础人设、经历与人际关系的理解和运用，以及写作手法、写作素材的“先索引、后正文”读取。
- 在已有角色、物品、地点目录内按大纲方案保存改编信息，随相关规划保存与修改共同维护。
- 以稳定来源章节锚点表达单章改编与原作两章之间的原创，按需读取原作和当前改编方案。

不实现共享素材库、向量检索、正文写作或原作全量加载；不自动移动历史素材，不新建角色、物品、地点，不修改已有基础资料及原作提取的经历和关系。

## 当前行为与证据

- 优化前，[规划助手](../../packages/neuro-book/assets/workspace/.nbook/agent/profiles/builtin/outline.planner.profile.tsx)与三个专家持有 read 和规划领域工具；专家 lorebook 写工具允许在整个 lorebook 内创建与编辑 Markdown，需要收窄。
- [素材提取规范](../specs/inspiration/material-extraction.md)：角色基础人设位于角色主文件，原作经历与关系在 experience、relationship 子目录；两类 note 素材有分类目录及根目录索引。
- [大纲提取规范](../specs/inspiration/outline-extraction.md)：提取大纲进入规划库，通过稳定方案与条目 ID 访问，不以 lorebook 笔记替代。
- [规划条目](../../packages/neuro-book/server/outline/format.ts)与[事务](../../packages/neuro-book/server/outline/transaction.ts)已有稳定 ID、版本、hash、备份 journal 与撤销基础。

## 方案、备选方案和取舍

### 素材读取和运用

基础人设用于身份、动机、底线、能力与行为选择；原作经历用于理解形成原因与成长机制；关系记录用于理解人物合作、对抗及变化的因果。依任务逐步读取，不默认读取全部角色或时间线。资料未读或缺失时不能声称已知。

写作手法与写作素材先读取 `lorebook/note/写作手法索引.md`、`lorebook/note/写作素材索引.md` 中相关内容，再按实际路径读取候选正文。索引用于筛选；采用前阅读正文并说明用途、适用条件及转化方式。委派专家交付具体素材路径、来源章节、目标方案、保留项与变化项。

### 对象权限与按方案维护

规划助手和专家不能新建角色、物品、地点，也不能更改已有基础信息。缺少对象时推荐用户先到设计工作台创建。新的计划经历、关系与状态信息只写入既有对象的以下子目录：

```text
lorebook/character/<对象>/改编中的新经历/<方案 ID>/……
lorebook/character/<对象>/改编中的新人际关系/<方案 ID>/……
lorebook/item/<对象>/改编中的内容/<方案 ID>/……
lorebook/location/<对象>/改编中的内容/<方案 ID>/……
```

使用稳定方案 ID，名称供阅读。每份记录关联产生它的规划条目，修改时替换该条目的记录，不反复追加旧版本。新信息表达方案计划，不自动等同于正文已发生事实。基础能力或固有效果需要改动时交回设计工作台，不用改编记录绕过限制。

### 改编来源与章节位置

原创/改编与讨论/自动是独立维度。改编时明确来源方案，以及基于哪个原作章节，或原创于哪两个原作章节之间；不明确才询问，用户已给出的定位不重复追问。同一原作区间已有新增章节时，还需明确在当前改编方案的实际插入位置。

保存稳定来源条目 ID，当前方案的顺序另由现有 placements 和线路表达，不能用显示章号代替身份。读取对应原作章节及必要前后章、当前改编对应章与实际相邻章、涉及人物和物品地点的方案记录；按依赖继续补读。检查信息披露、动机、关系、资源状态、重复事件及伏笔顺序。

备选方案：另建改编角色被开发者否定；全项目共用一套改编记录被否定；直接改写基础资料被否定；每次全量读取素材不采用。共享库和向量检索另见 [后续灵感](shared-material-library-vector-search.md)，不作为本轮依赖。

## 数据、接口、安全、迁移、发布与回滚影响

- 为规划条目增加可选改编来源和关联素材的新信息，旧条目无新增字段仍可读；普通编辑未传相关字段保持原值。
- 角色、物品和地点需真实存在，路径和方案归属由服务端校验，不开放通用写权限。相关规划与改编文件一起进入版本校验、历史与撤销。
- 新增受控素材概览与分页读取入口，现有笔记索引可复用；不让 Agent 猜路径或把索引摘要当正文。
- 本轮不迁移用户数据。旧运行期会话中的通用 lorebook 写工具也必须受到新边界限制。
- 发布与真实模型验收另行授权；本轮以 Mock、临时项目和聚焦浏览器检查验证。

## 对 Spec 的预期改动

新增 [outline.material-adaptation](../specs/outline/material-adaptation.md)，更新规划 Agent 合同中的素材写入边界与引用入口。验收覆盖新对象与基础文件写入拒绝、各方案记录隔离、修改同步与撤销、来源章节稳定定位、索引分页和按需正文读取。
