# 摘要模型与自定义 Provider 配置

状态：accepted。摘要模型独立选择与 Custom Provider 空模板已授权实施。

## 背景

上下文管理会在会话运行期间生成摘要。摘要调用应能使用专门配置的模型，避免和主 Agent 共用模型时受限于成本、上下文窗口或推理能力。现有 Provider 页面虽然提供模板，但冷门服务商需要自行填写 API 地址、协议和模型信息，不能依赖固定模板。

## 已确定行为

- 配置作用域为全局，保存位置仍是 Workspace Root 的 `.nbook/config.json`。
- 全局设置新增“摘要模型”入口。它只选择一个已经在 Provider 页面配置并启用的 `provider/model`，不新增 API 凭证配置。
- 选择为空时，摘要沿用摘要 Profile 或全局默认模型。新的摘要运行读取最新配置；已经开始的摘要任务不被切换中的设置打断。
- Provider 列表保留“Custom Provider”空模板。创建后用户可以填写或修改 API Base、代理、协议格式、凭证、请求参数和模型清单；模型仍须满足现有运行时合同后才能调用。
- Provider API Key 继续按现有脱敏规则保存和展示。空白输入不会覆盖已保存密钥，显式清除仍使用原有清除操作。

## 数据与运行时合同

全局 `agent.summarizerModelKey` 保存摘要模型引用。它必须是已启用模型的完整 key；设置页的候选直接来自当前模型快照。Harness 启动摘要 invocation 时把该引用作为本次调用的模型覆盖，因此不会修改会话原有模型绑定。

Provider 空模板复用现有 `models.providers` DTO、模型能力校验、引用检查和保存流程。模板只是创建草稿的起点，保存后的 Provider 不携带模板锁定状态。

## 方案取舍

摘要模型没有另建一套 API 配置，因为 Provider、凭证脱敏和模型能力校验已经是现有系统的稳定边界；新增字段只保存模型引用，能够同时覆盖云端、局域网和本地兼容服务。Provider 连接参数允许直接修改，保留 Provider ID 不可改的约束，以避免悄悄破坏已有 `provider/model` 引用。

## 验收

1. 在全局配置的“摘要模型”中能看到当前已启用模型，选择并刷新后仍保持选择。
2. 清空摘要模型后，摘要回退到原有 Profile/默认模型。
3. 使用 Custom Provider 创建连接，填写 API Base、协议和模型能力字段后可以保存；重新打开设置仍可修改 API Base 和代理。
4. 缺少模型 API、输入类型、上下文窗口或最大输出等必要字段时，继续由现有 Provider 校验提示，不因新增入口绕过校验。

## 非目标

本轮不改变摘要触发阈值、压缩算法、项目级摘要模型覆盖，也不实现新的 Provider 协议适配器。DeepSeek Harness 上下文裁剪策略另按上下文管理任务推进。
