# 写作角色模型设置

写作会话底部输入区下方左侧的图标按钮和弹出面板，用来分别设置主创、助手、写手三个角色的模型、思考和温度。设置保存在本作品的 Project Config，只影响这三个写作 Profile。

## 布局

触发器是“滑杆”图标按钮，面板优先向上展开，与按钮左侧对齐并避让视口边界。面板自上而下：

1. 标题“模型设置（本作品）”。
2. 三组，每组一个角色名，下面是模型下拉；再下一行是思考下拉和温度输入。
3. 一行说明：空白沿用全局设置，主创的新设置从下一轮回复开始生效。
4. 错误提示（有时）。
5. “取消”“保存”。

面板宽度不超过 320px，窄屏按视口收窄。

## 交互

- 打开面板时读取设置；每次打开都重新读取，丢弃上次未保存的修改。
- 模型与思考下拉的第一项是“沿用默认（当前生效值）”；思考里的“关闭思考”对应 `off`。
- 温度留空表示沿用默认，填写须在 0 到 2 之间，否则保存时提示，不发请求。
- 只有改动过的角色才会保存；没有改动时“保存”不可点。每保存一个角色发出一次 `saved`。
- 保存成功后关闭面板；失败时面板保持打开并显示原因。

## 数据

```ts
type Props = {
    /** 当前作品；为空时按钮不可点。 */
    projectRoot: string | null;
    /** 为真时按钮不可点，例如主创正在回复。默认 false。 */
    disabled?: boolean;
};

type Emits = {
    /** 某个角色的设置已保存。 */
    (e: "saved", role: WritingRole): void;
};
```

没有 slots 和 expose。attrs 没有稳定的透传位置，不应依赖。

## 状态

- 读取中：面板里显示 `role="status"` 的载入提示。
- 没有启用的模型：提示先在设置中配置模型，下拉只剩“沿用默认”。
- 保存中：控件禁用，“保存”显示加载。
- 读取或保存失败：`role="alert"` 显示原因。

## 不支持

- 不改其他 Profile，也不改 topK、stream 等字段。
- 不做全局设置；全局设置仍在设置页的 Agent Profile 里。

## 隐藏通道理由

- `io:read` / `io:mutate`：设置经写作 API 客户端读写，fetch 可注入，测试据此替换。
