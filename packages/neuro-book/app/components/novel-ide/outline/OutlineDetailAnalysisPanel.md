# 细纲偏差分析面板

细纲正式采用前的偏差分析与采用确认，挂在大纲库面板的细纲表单下方。分析用当前默认模型对照所属章节大纲找出偏离和冲突；采用必须附带这份报告，偏离要确认、冲突要逐条说明处理方式。报告绑定细纲内容哈希，细纲一变旧报告作废。

## 布局

- 已采用：标题“已正式采用”，其下是分析摘要和各冲突的处理记录。
- 草稿：标题行“正式采用前的偏差分析”和“开始分析”（有报告时为“重新分析”）按钮。章节大纲未采用时按钮不可点，下方写明原因。有报告时依次显示：从操作行采用时的提示、摘要、待补参考资料（警示色，不阻止采用）、偏离列表与确认勾选、冲突列表（每条一个处理方式下拉和说明输入框）、“正式采用细纲”按钮。

## 交互

- “开始分析”调用 `analyze-detail`，拿到报告后重置偏离确认与冲突处理。
- “正式采用细纲”在偏离已确认、每条冲突都填了说明后才可点，调用 `adopt-detail`。
- `analyzeAndAdopt()`：供大纲库操作行的“正式采用”调用。方案修订号未变时沿用已有报告，否则重新分析；没有偏离和冲突就直接采用，否则显示提示“分析发现偏离或冲突，处理后点“正式采用细纲”。”并把面板滚入视野。
- 细纲内容哈希变化时清空报告、确认与提示。

## 数据

```ts
type Props = {
    /** 大纲写入动作，分析与采用都经它发起 */
    actions: OutlineWorkbenchActions;
    planId: string;
    /** 当前方案修订号，受控 */
    revision: number;
    /** 选中的细纲及其内容哈希，受控 */
    record: {contentHash: string; value: OutlineWorkbenchEntry};
    /** 所属章节大纲是否已采用；只用于提示，能否分析以服务端为准 */
    chapterAdopted: boolean;
};
```

没有 emits 和 slots。expose `analyzeAndAdopt(): Promise<void>`。attrs 透传到根 `section`。

## 状态

- 未分析：只有标题行。
- 分析或采用失败：错误由 `actions` 显示，本地报告保留。

## 不支持

- 不在面板里修改细纲；冲突“已在细纲中处理”只是记录说明，修改细纲后需重新分析。
