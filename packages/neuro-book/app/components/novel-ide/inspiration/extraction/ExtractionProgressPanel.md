# 提取进度面板

大纲提取和素材提取共用的进度展示：整体进度、按分组（卷或分块）统计、逐项状态，以及取消、继续、失败项重试与跳过。面板只展示 `ExtractionProgress` 并上报操作，不请求服务，也不轮询。

## 布局

自上而下：任务状态徽章与整体进度条（“已处理 x / 共 y”）；停止原因或中断提示；分组统计行（每组一个徽章，带完成数 / 总数）；逐项列表，上方有“进行中与失败 / 全部”切换；操作按钮行（取消、继续）。逐项列表每行是单元名、状态徽章和失败时的错误摘要，失败项右侧有“重试”“跳过”。`390×844` 下每行换行，列表自身可滚动，页面不出现横向滚动。

## 交互

- 任务运行中显示“取消”；已中断、已取消、部分失败时显示“继续”，继续只会重新执行未完成的单元。
- 失败项的“重试”重新执行该单元；“跳过”表示放弃它的成果，之后任务可以在缺少它的情况下继续。
- “逐项状态”栏同时提供“一键重试（数量）”“一键跳过（数量）”。按钮针对点击时所有失败项，不受列表筛选影响；上报失败单元 ID 快照，由宿主一次请求处理。运行中、待确认和部分失败状态可使用；请求期间或没有失败项时禁用，已取消／中断时先继续任务。跳过不删除已成功产物。
- 列表默认只列出进行中和失败的项，避免上百章时淹没关键信息；切到“全部”可看到每一项。
- 已中断（服务重启或进程退出）时用提示条说明“任务被中断，已完成的部分都已保留，点继续即可接着做”。

## 数据

```ts
type Props = {
    /** 服务端进度投影；null 表示尚未开始 */
    progress: ExtractionProgress | null;
    /** 请求进行中，禁用全部操作 */
    busy?: boolean;
    /** 分组键的显示名，缺省原样显示 */
    groupLabel?: (group: string) => string;
};
type Emits = {
    (event: "cancel"): void;
    (event: "resume"): void;
    (event: "retry-unit", unitId: string): void;
    (event: "skip-unit", unitId: string): void;
    (event: "retry-failed", unitIds: string[]): void;
    (event: "skip-failed", unitIds: string[]): void;
};
```

没有 slots 和 expose。

## 状态

- 无进度：显示空状态“尚未开始”。
- 运行中 / 等待确认 / 已完成 / 部分失败 / 已取消 / 已中断：徽章和进度条色调随状态变化；等待确认时附带服务端给出的等待原因。
- 有停止原因（来源变化、模型不可用、意外错误）时显示对应说明和服务端原始消息。

## 不支持

不展示模型调用细节和单元的中间数据；不提供拖动调整顺序或并发度。
