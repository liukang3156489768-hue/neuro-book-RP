# 大纲提取视图

“作品提取”里的大纲提取一栏：把一部作品按章节拆开，经划卷确认后让模型逐章提取细纲、章节大纲，再汇总出卷纲和总纲，结果写成一个大纲方案。视图按任务阶段切换内容：尚未开始时是设置（章节、划卷、数据去向、作品名），任务开始后是进度，等待覆盖确认时是新旧对比，结束后是结果卡片。它与素材提取是两个互不阻塞的独立视图。

## 布局

设置阶段先选择切分方式并查看预览，再自上而下完成四步：1 章节（可修正）或按字数分块（默认目标约 5 万字）、2 划卷、3 数据去向（仅当该来源已有提取过的方案时出现）、4 作品名与“确认划分并开始提取”。两种模式都显示块号、P 范围和字数；有章节时按字数分块也不会拆开完整章节，超长章节独立成块，无章节时按完整段落分组。任务阶段：状态与进度面板；如果在等待覆盖确认，下面是新旧对比；提取结束后是结果卡片和“返回设置”（重新提取）。`390×844` 下各步纵向堆叠，不出现横向滚动。

## 交互

- 章节修正、划卷草稿的任何改动都会让控制器延迟向服务端校验划卷，服务端说明实时显示在划卷编辑器下方。
- “开始提取”前控制器会再校验一次，失败原因显示在按钮上方，任务不会启动。
- 选择覆盖已有方案时，任务会在提取完成后暂停等待确认；确认前不会改动任何已有内容。
- 任务运行中可取消；已中断、已取消或部分失败的任务可以继续；失败的单元可单独重试或跳过。
- 进度面板的“一键重试／一键跳过”对点击时的所有失败单元一次提交；不会重做已成功单元，也不包含点击后新产生的失败单元。
- “返回设置”只离开当前任务的结果视图，任务记录保留在服务端，再次选择该来源会恢复它。
- 模型旁的大纲任务列表由宿主提供；选择历史任务只展示该任务的进度、覆盖对比及方案结果。新建任务使用独立设置，历史任务不阻碍进入设置，服务端仍保持同来源同时一个运行中大纲任务的约束。

## 数据

```ts
type Props = {
    /** 大纲提取控制器，来自 useInspirationExtraction().outline；视图读取其状态并调用其动作 */
    outline: OutlineController;
    /** 提取使用的模型；缺省走服务端默认模型 */
    modelKey?: string;
};
type Emits = {
    (event: "open-plan", plan: {planId: string; planTitle: string}): void;
};
```

控制器对象就是本视图的“函数式 emits”：用户操作直接调用控制器的动作（`addCorrection`、`startOutline` 等），本视图自己不发请求，也不保存业务状态，只保存“正在查看哪一步”之类的纯展示状态。没有 slots 和 expose。

## 状态

- 没有选择来源：显示空状态。
- 来源没有可划分的内容：显示服务端错误。
- 任务状态：提取中、等待确认、已完成、部分失败、已取消、已中断，分别由进度面板和结果区域呈现。

## 不支持

大纲本轮始终提取整部作品，不支持在此处选择或排除块；不在此处编辑提取结果；提取完成后用“打开提取方案”到大纲工作台中查看和修改。
