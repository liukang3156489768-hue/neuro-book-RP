# 待写入审阅清单

素材整合完成后，所有候选条目列在这里等你审阅：勾选要写入 lorebook 的条目，编辑、删除、拆分有问题的条目，把重复的条目合并，最后确认写入。组件是纯展示，所有改动都以动作上报，由宿主请求服务端并把更新后的清单传回来。

## 布局

顶部工具栏：汇总（已选 x / 共 y、已写入 z）、“全选”“全不选”、“合并所选”和“确认写入 N 项”。其下按类别分组，每组一个标题，组内每个条目一行：写入勾选框（标题）、类别徽章、写入状态徽章（待写入、已写入、已跳过、写入失败）、目标目录、别称，以及行内按钮“编辑”“拆分”（仅角色）“删除”和一个“选作合并”复选框。写入失败的条目下方显示服务端给出的原因。点击“编辑”或“拆分”在该行下方展开编辑器。`390×844` 下一行内容换行，不出现横向滚动。

## 交互

- 默认所有条目都已勾选写入（服务端整合完成时的初始状态）；勾选框的变化立刻上报 `select` 动作并持久化。
- “选作合并”是纯本地的勾选，与是否写入无关；至少选中两个同类别条目，“合并所选”才可用，上报 `merge` 动作，由服务端调用模型合并基本设定。
- “编辑”展开字段编辑器；“拆分”只对角色条目出现；“删除”上报 `remove`，删除前不再二次确认，因为条目可通过重新提取找回。
- 已写入的条目是锁定的：不可勾选、编辑、删除或合并，只显示“已写入”。
- “确认写入”上报 `write`，由宿主先检查同名冲突再写入；没有勾选任何可写入条目时不可用。

## 数据

```ts
type Props = {
    review: MaterialReview;
    busy?: boolean;
    /** 服务端对上一个动作的拒绝原因，展示在展开的编辑器里 */
    error?: string;
};
type Emits = {
    (event: "action", action: MaterialReviewActionDto): void;
    (event: "write"): void;
};
```

没有 slots 和 expose。每个动作只携带条目 ID 和内容，不携带确认者。

## 状态

- 空清单：显示空状态“没有待写入的条目”。
- 正在编辑的条目被改动或消失后自动收起编辑器；改动其他条目的勾选不打断编辑；动作失败时编辑器保留并显示 `error`。
- `busy`：所有按钮和勾选不可用。

## 不支持

不支持在清单里新建条目、调整条目所属类别或目录名；目录名由标题自动得出。
