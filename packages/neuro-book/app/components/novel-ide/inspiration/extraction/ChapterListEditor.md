# 章节列表与章节修正

大纲提取的第一步：显示系统从来源识别出的章节（标题、P 段落范围、字数），并让用户修正识别错误。修正以“按顺序重放的操作列表”表示，每次修改都由宿主重新向服务端预览，组件自己不计算章节。

## 布局

自上而下：识别摘要（共多少章、多少卷标题行、是否按字数分块）、章节表、修正区、已做修正列表。章节表有序号、标题、P 范围、字数、操作五列，超出最大高度时在表内滚动。修正区是一行：段落编号输入、标题输入、“设为章标题”和“在此拆分”两个按钮，输入段落编号后下方显示该段落开头的原文。`390×844` 下表格在自身容器内横向滚动，修正区各项上下排列，页面本身不出现横向滚动条。

## 交互

- 每一行的“取消章标题”（仅有标题行的章可用）和“与下一章合并”（最后一章不可用）直接上报修正。
- 在修正区填写段落编号（`P12` 或 `12` 均可）后，“设为章标题”把该段落当作章标题，“在此拆分”从该段落起另起一章；标题可留空，留空时沿用段落原文。
- 已做修正按顺序列出；“撤销上一项”只撤最后一项，“全部还原”回到系统识别的原状。修正按顺序重放，所以不提供撤销中间某一项。
- 服务端拒绝某项修正时，宿主保持原列表并通过 `error` 显示原因，不会留下半个修正。

## 数据

```ts
type Props = {
    preview: StructurePreview | null;
    corrections: ChapterCorrectionDto[];
    /** 重新预览中，按钮暂不可用 */
    loading?: boolean;
    /** 最近一次修正失败的说明 */
    error?: string;
    /** 按 P 编号取段落原文；来源段落尚未载入时返回 null */
    paragraphText?: (paragraphId: string) => string | null;
};
type Emits = {
    (event: "correct", correction: ChapterCorrectionDto): void;
    (event: "undo"): void;
    (event: "clear"): void;
};
```

没有 slots 和 expose。

## 状态

- 没有预览：显示“选择来源后显示章节”的空状态。
- 字数模式（没有识别到章节）：表中是按字数切出的块，并提示可以用“设为章标题”补出章节，补出后自动变为章节模式。
- 段落编号格式不对或段落不存在：输入下方提示，按钮不可用。

## 不支持

不直接编辑章节标题文字（需要时对标题行“设为章标题”并填写新标题），也不支持拖动调整边界。
