# 各级大纲正文模板

本文件说明 `create-entry` / `edit-entry` 的 `body` 怎么写，以及各级建议填哪些元数据字段。设计依据是 `docs/specs/outline/outline-entry-templates.md`。

模板是建议结构，服务端不检查标题。用户已有自己的写法时沿用用户的写法，只补缺失的要素。正文里不写 frontmatter，也不写 `id`、`status`、`version`。

## 通用要求

- 先读上级：写卷纲前读总纲，写章节前读所属卷纲（或总纲），写细纲前读所属章节。用 `get_planning_context` 的 `entryIds` 读正文。
- 下级展开上级，不改写上级已定的走向。确实需要改动时，把理由写进回复或 `openQuestions`，由用户决定是否先改上级。
- 每级只写本级该决定的事，细节留给下一级。
- 引用 `lorebook/` 素材前先用 `read_planning_material` 读取确认。没有来源时写待补参考，不编造设定或路径。

| 层级 | 建议篇幅 | 父级 |
| --- | --- | --- |
| 总纲 `total` | 1000-3000 字 | 无 |
| 卷纲 `volume` | 800-2000 字 | 总纲 |
| 章节 `chapter` | 500-1500 字 | 总纲或卷纲 |
| 细纲 `detail` | 按场景数量，每场景约 300-800 字 | 章节 |

## 总纲

作品整体的故事方向，所有方案共用。聚焦宏观结构：说清核心冲突，而不是罗列事件；给出结局方向，但不锁死具体结局，为方案展开留空间。不写具体章节情节、细节描写和对话。

```markdown
# 核心冲突

[作品的核心矛盾是什么，谁和谁、为什么不可调和]

# 主题

[作品想表达的核心主题和价值取向]

# 主要阶段

## 第一阶段：[阶段名]
[阶段目标与转折]

## 第二阶段：[阶段名]
[阶段目标与转折]

## 第三阶段：[阶段名]
[阶段目标与转折]

# 结局方向

[预期的最终状态]

# 人物关系

[主要人物之间的关系网络]

# 世界观设定

[世界观基础设定]
```

核心冲突、主题、结局方向必须有；主要阶段建议 3-5 个。元数据一般只需 `materialRefs`（全局核心素材）。

## 卷纲

总纲下的一个阶段：本卷的目标、冲突、推进和收束。写清边界（起始和结束状态）以及本卷在全书中的作用，不写具体章节内容和场景描写。

```markdown
# 本卷目标

[本卷要达成的故事目标]

# 起始状态

[本卷开始时的人物与世界状态]

# 核心冲突

[本卷的主要矛盾]

# 剧情推进

## 起
[如何引入冲突]

## 承
[冲突如何发展和升级]

## 转
[关键转折]

## 合
[如何收束]

# 结束状态

[本卷结束时的人物与世界状态]

# 与总纲的关系

[本卷在全书中的位置和作用]

# 关键事件

- [事件]
- [事件]
- [事件]
```

本卷目标、起始状态、核心冲突、结束状态必须有；关键事件建议 3-5 个。元数据可选 `materialRefs`、`targetWords`（本卷目标字数）。

## 章节大纲

可以直接进入线路、交给正文的剧情单元，与正文一章对应。写清本章发生什么、冲突和结果，场景划分要能直接展开成细纲。

```markdown
# 章节目标

[本章要达成的具体目标]

# 场景设定

**时间**：[时间]
**地点**：[地点]
**出场人物**：[人物]

# 剧情概要

[本章完整剧情流程，200-500 字]

# 关键场景

## 场景一：[场景名]
**目标**：[场景目标]
**冲突**：[场景冲突]
**结果**：[场景结果]

## 场景二：[场景名]
**目标**：……
**冲突**：……
**结果**：……

# 人物变化

**主角**：[状态变化]
**其他角色**：[变化]

# 伏笔处理

**埋设**：[本章要埋下的伏笔]
**回收**：[本章要回收的伏笔]

# 章节结尾

[本章如何结束，给下一章留下什么]
```

- 章节目标、场景设定、剧情概要、章节结尾必须有；关键场景建议 2-5 个。
- 元数据建议填 `materialRefs`、`writingGuidance`、`targetWords`，可选 `references`（整章参考，不带 `marker`）。
- “伏笔处理”一节用文字说明意图即可。正式的伏笔标记由伏笔工具放进正文（见 SKILL.md 的“伏笔”一节），不要在新建时手写 `nb:foreshadow` 标记。

## 细纲

写正文前的最后一级规划，依托所属章节细化，也是写作模块的直接输入。细纲的全部写作信息都写在正文里，按下面的模板书写；不要用 `writingGuidance`、`references`、`targetWords` 等元数据字段，细纲上这些字段不会保存。细纲要完成必要的剧情决定，但不逐句指定措辞。细纲会先经过与章节大纲的偏差与冲突分析，用户处理后才能采用，所以不要偏离章节已定的走向。

```markdown
# 章节总览

- 章节标题：[章节名称]
- 剧情概括：[本章剧情的大致概括]
- 核心冲突：[本章的核心矛盾或核心事件]
- 情绪基调：[本章的情绪基调或情绪演变过程]
- 目标字数：[整章正文的目标字数，正整数]

# 章节细纲

## 场景1：[场景名]

- 场景简述：[这个场景发生什么、要达到什么效果，一两句]
- 字数要求：[本场景目标字数]
- 人称要求：[例如：第三人称限知，跟随林辰]
- 情绪基调：[可选]
- 剧情节奏：[可选，例如：先缓后急]

### 场景地点

- 地点名称：[场景实际地点]
- 具体位置：[例如学校教室后排，不展开全校]
- 地点资料：[地点名称](已有地点主文件路径)
- 与前文的衔接：[原地延续或移动顺序]
- 本场景相关条件：[只写影响本场景的空间条件]

### 参与角色

- [角色名]：[本场景中的目的]
  - 角色资料：[角色名](已有角色主文件路径)
  - 当前状态：[可选，简述]
  - 外貌要求：[可选，简述]

### 角色服饰与外观状态

- [角色名]：[指定穿着或延续前文，相关外观状态与变化；不展开整份资料]

### 具体情节

1. [第一个情节节拍]
2. [第二个情节节拍]
3. [最后一条是本场景的结尾落点]

### 描写

[可选：需要重点描写的环境、动作、心理]

### 写作指导

[可选：展开还是略写、使用的手法和重点]

### 参考资料

- [资料说明](lorebook/……/文件.md)
- [还没有来源的资料，只写说明]

### 伏笔

- [伏笔名称]
  - 标记：[章节大纲里的伏笔标记 ID，例如 fm-01]
  - 状态：[埋设、强化或回收]
  - 作用：[这个伏笔在全书里的作用]
  - 效果：[本章要达到的效果，例如随口一提、不解释、留下悬念]

## 场景2：[场景名]

……

# 禁止事项

- [本章不能出现的情节结果]
```

结构规则（不满足时不能分析、采用和写作）：

- 一级标题只能是 `# 章节总览`、`# 章节细纲`、`# 禁止事项` 三个，各一个；第一个一级标题前不能有内容。
- 章节总览必须写目标字数，它就是整章正文的目标。各场景字数要求之和与它相差超过上下 50% 时会提示。
- 场景是 `# 章节细纲` 下的二级标题，写成 `## 场景1` 或 `## 场景1：名称`，编号从 1 起连续。
- 每个场景必须写场景简述、字数要求、人称要求，并且至少一条具体情节。其余字段和小节可以留空。
- 场景小节为场景地点、参与角色、角色服饰与外观状态、具体情节、描写、写作指导、参考资料、伏笔；其他小节不会交给写作。
- 场景地点简述位置、必要条件与移动顺序，可附已有地点文件链接；角色按名引用已有资料。服饰和外貌只写本场景要求，完整资料由写作助手读取并经独立审核后补充给写手，不复制整份档案。
- 具体情节逐条成为写作时必须写到的要素，最后一条是场景的结尾落点：写手只写到这里，可以在结尾铺垫下一场景，但不展开下一场景的剧情。

伏笔：

- 细纲正文不写伏笔标记。伏笔标记只在章节大纲正文里，细纲在场景的 `### 伏笔` 里认领由本场景执行的标记。
- `标记` 必须是章节大纲里已有的伏笔标记 ID；`状态` 必须与这个标记的动作一致（`plant` 埋设、`reinforce` 强化、`recover` 回收），否则不能采用。
- `作用` 只交给写作助手审阅，写手看不到，所以可以写伏笔将来要揭示的内容；`效果` 会交给写手，只写本章要呈现到什么程度，不写后续真相。
- 把章节大纲的每个伏笔标记分给实际执行它的场景；漏分的写作前会被提示。

禁止事项：

- 只写本章不能出现的情节结果，用来防止写作时误读细纲把剧情写偏。例如情节是主角潜入刺杀，禁止事项可以写“主角不能被抓住或被杀死”。
- 不写文风或写法限制（例如“不用比喻”“少写心理”），这些放进文风文件或场景的写作指导。
- 每个场景都会带上全部禁止事项，审阅时逐条检查。

参考资料：

- 每项写成 Markdown 链接，路径是项目内相对路径，先用 `read_planning_material` 读取确认。
- 找不到来源时只写说明、不写链接，它会作为待补资料提示，不阻止采用。不编造路径。

生成后运行与章节大纲的偏差分析。一章只写一份细纲：写作时一章有多份细纲会被阻断。

## 新建示例

在章节 `ol-ch-003` 下新建细纲（`planId`、`expectedRevision` 取自当前快照；`fm-01` 是章节大纲正文里已有的伏笔标记，动作为 `plant`）：

```json
{
  "operation": "mutate",
  "expectedRevision": 12,
  "action": {
    "kind": "create-entry",
    "planId": "plan-...",
    "parentId": "ol-ch-003",
    "entryKind": "detail",
    "title": "第三章 夜访 - 细纲",
    "materialRefs": ["lorebook/character/lin-chen.md", "lorebook/location/lin-manor.md"],
    "body": "# 章节总览\n\n- 章节标题：夜访\n- 剧情概括：林辰向父亲求证身世被拒，发现密信后雨夜出府。\n- 核心冲突：林辰追问真相与父亲守口如瓶\n- 情绪基调：压抑转为决绝\n- 目标字数：3000\n\n# 章节细纲\n\n## 场景1：书房对峙\n\n- 场景简述：林辰追问身世，父亲以祖训回绝，林辰意外看到密信。\n- 字数要求：1800\n- 人称要求：第三人称限知，跟随林辰\n- 情绪基调：压抑\n- 剧情节奏：慢\n\n### 参与角色\n\n- 林辰：问清自己的身世\n- 父亲：守住秘密\n\n### 具体情节\n\n1. 林辰进书房追问身世\n2. 父亲引用祖训拒绝回答\n3. 林辰发现书桌上的密信\n4. 林辰把密信藏进袖中\n\n### 参考资料\n\n- [林府布局](lorebook/location/lin-manor.md)\n- 林家祖训原文\n\n### 伏笔\n\n- 密信\n  - 标记：fm-01\n  - 状态：埋设\n  - 作用：密信出自林辰生母，第八章揭示\n  - 效果：只写信封上的陌生火漆，不写内容\n\n## 场景2：雨夜出府\n\n- 场景简述：林辰避开巡夜家丁离府。\n- 字数要求：1200\n- 人称要求：第三人称限知，跟随林辰\n- 剧情节奏：快\n\n### 具体情节\n\n1. 林辰避开巡夜家丁\n2. 林辰消失在雨巷尽头\n\n# 禁止事项\n\n- 父亲不能说出密信的来历\n- 林辰不能在本章读到密信内容\n"
  }
}
```

祖训原文还没有素材，所以参考资料里只写说明，作为待补资料。
