# ADR 0022：大纲规划模块的结构化文件真相源与关系边界

- 状态：Accepted
- 日期：2026-09-24
- 决策来源：开发者确认大纲模块与现有 Plot 不冲突、结构化文件为规范来源、SQLite 仅作索引、对象删除与关系删除分离，并授权由 Agent 选择具体文件格式与标记语法。
- 关联 Proposal：[大纲规划模块](../../../../docs/proposals/outline-planning-module.md)
- 关联行为规范：[大纲库与细纲](../../../../docs/specs/outline/planning-library.md)、[伏笔库与标记派生](../../../../docs/specs/outline/foreshadowing.md)、[线路规划](../../../../docs/specs/outline/line-planning.md)

## 背景

大纲规划模块需要同时满足三项要求：用户可以审阅和修改底层文件，Agent 可以稳定解析并生成规划数据，UI 与查询又需要按项目快速索引。现有 Plot 已承担作者视角的剧情组织、Scene、Promise、Decision、World Engine 关联和 Writer Brief，不需要被大纲规划模块替换或重新建模。

如果把规划对象只放在 SQLite，会削弱作品文件的可审阅性和可携带性；如果把每个界面状态都保存成独立副本，又会造成文件、数据库和 UI 三套真相源。因此本 ADR 固定文件、索引、关系和标记的边界。

## 决策

1. **结构化文件是唯一规范来源。** 规划对象、对象间引用、线路节点与边、正式标记和版本信息必须能够从项目文件完整重建。SQLite 只保存可重建索引、查询加速数据和解析摘要，不拥有规划正文或关系的最终决定权。
2. **规划文件使用可审阅的 YAML + Markdown 组合。**
   - `outline/manifest.yaml` 保存模块版本、当前规划版本和顶层目录索引。
   - `outline/entries/<slug>--<stable-id>.md` 保存总纲、卷纲、章节大纲和细纲；YAML front matter 保存结构化字段，Markdown 正文保存叙述内容。
   - `outline/foreshadowing/<slug>--<stable-id>.md` 保存伏笔定义、设计说明和汇总元数据；埋设/强化/回收事实仍只来自章节大纲正式标记。
   - `outline/graphs/<slug>--<stable-id>.yaml` 保存每个方案唯一的线路图：节点（关联条目或为空）、所在格号与行号，以及从小格号指向大格号的连线。格号是方案内的全局剧情顺序，行号只是排版。
   - `outline/storylines/<slug>--<stable-id>.yaml` 保存线路：标题、类型、固定状态、勾选的节点 ID 和分析报告。线路内顺序由节点格号派生，不另存。
   - （2026-09-26 修订：此前每条线路自带节点与边、存于 `outline/lines/`，线路之间无法分叉、汇合，也没有跨线路的先后。开发者确认改为方案级共享节点图加横向分格，旧文件不兼容，保留在磁盘但不再读取。）
   - Agent 建议、分析报告和历史快照不得覆盖规范文件；它们通过既有历史/会话机制或独立的派生报告保存，并带输入版本。
3. **稳定 ID 与文件名分离。** 稳定 ID 生成后不因移动、重排、改名或关系变化而改变。文件名使用可读 slug 加稳定 ID；写时分叉生成新稳定 ID 和新文件名，源文件保持不变且不重新合并。
4. **全局总纲唯一，方案链只拥有关系。** 作品规划范围内只有一个总纲对象；方案 A/B 等多条方案链表示完全不同的展开，通过 manifest 中的 placement/关系共同引用该总纲，并各自组织卷纲和章节大纲。创建方案链不得复制总纲对象；删除总纲仍按对象删除处理并需要二次确认。
5. **对象删除与关系删除分开。** 对象删除是删除该对象的规范文件，只有在所有活动引用已解除并完成影响预览、确认和历史快照后才允许执行；关系删除只移除父子、引用、节点关联或线路成员关系，对象文件继续存在。任何操作不得隐式级联删除共享对象。
6. **伏笔标记使用 Markdown 注释包围可见文本。** 正式章节大纲正文采用以下形式：
   ```markdown
   <!-- nb:foreshadow marker="fm-01" foreshadow="fo-001" action="plant" -->银纹<!-- /nb:foreshadow marker="fm-01" -->
   ```
   `action` 允许 `plant`、`reinforce`、`recover`；`marker` 在文档内唯一；开始和结束注释必须成对，标记内容可以在 UI 中渲染为下划线并显示关联信息。损坏、未知伏笔 ID、未知动作或未成对标记不得静默转为正式事件。
7. **伏笔顺序以线路图格号为准。** 大纲库层级不是时间线。标记是否满足“先埋设后回收”以同一方案中有效固定线路节点的格号判断，可以跨线路；同格不同节点不算“之后”，同一节点内按标记位置判断；没有可确定顺序的回收标记只能作为异常待处理，不得作为有效回收事件。（2026-09-26 修订：此前按单条线路内从左到右的顺序判断。）
8. **大纲规划模块与 Plot 互补而非替换。** 大纲规划模块拥有灵感大纲、细纲、伏笔标记和正式线路节点；Plot 继续拥有作者视角的 Story、Thread、Scene、Promise、Decision、World Engine 关联和 Writer Brief。首期不复制 Plot 实体、不改写 Plot 表、不建立第二套 Scene 真相源；跨模块只通过明确的只读交接或后续适配器传递稳定 ID 与版本。
9. **《新小说编写计划》是开发设计文档，不是规划数据。** 其中被本模块替换的大纲与细纲部分和伏笔部分不再是行为依据，其余部分仍是后续开发的设计依据。本模块不从它导入规划，也不修改它。（2026-09-26 修订：此前“提取旧文档内容生成迁移草案”的决定误把设计文档当作用户数据，已撤销，迁移功能已删除。）

## 后果与限制

- 作品目录可独立复制、审阅和恢复，文件损坏时可以从文件历史恢复；SQLite 索引损坏时必须删除并重建，不能反向覆盖规范文件。
- 自由编辑规范文件可能产生语法错误，因此读取必须先校验 schema 和引用，失败时保留原文并 fail-closed。
- 文件粒度增加了跨文件变更的一致性要求；正式保存需要在文件写入、历史记录和索引刷新之间提供事务或可恢复的提交边界。
- Plot 与大纲规划模块保持清晰边界后，首期不需要为“消除冲突”迁移现有 Plot 数据；后续若需要 Writer Brief 或 Scene 适配，必须单独建立合同和单向映射。

## 实施门禁

在 Phase 1 编码前，必须用确定性解析器验证上述目录、front matter、线路 YAML 和伏笔注释；实现不得先创建 Prisma 领域表再反向决定文件格式。任何新增规范字段先增加文件 schema 版本并保留旧版本读取或明确迁移失败行为。
