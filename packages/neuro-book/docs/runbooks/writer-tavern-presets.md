# 写手酒馆预设使用与验收

兼容范围与失败语义见[写手预设合同](../../../../docs/specs/writing/tavern-preset-compatibility.md)。当前实现仍待统一验收；使用兼容开发分支启动的源码应用，已有安装包不会因 worktree 中的修改自动更新。

## 导入与保存

1. 打开“配置中心 → 全局 → 提示词管理”，筛选写作模块。
2. 在“写手 · 场景正文”或“写手 · 局部改写”点击“导入酒馆”，选择原生 JSON。两个用途各自选择预设。
3. 检查宏身份和“写作条目映射”。默认 user 为作者、char 为写手；这是宏身份，不改变 API 消息角色，也不会自动指向小说中的某个人物。按类别逐条选择资料占位符、局部变量或全局变量；可点击条目名称查看原模板。
4. 检查条目顺序、启用状态、角色和正文；未排列条目可加入序列。可设置相对/深度注入、depth、order 和 generation triggers。启用新资料槽位时只补空绑定，不重置既有资料。
5. 点击预览，查看最终消息、变量终态、扩展依赖与生成参数；未提供的作品变量显示占位值。预览不调用模型。
6. 保存预设。开关、排序、正文与绑定一并保存；修改已有原生预设会增加其修订。未保存草稿不会作用于写手。

原生 JSON 保留未知字段。导出原生文件可以回到酒馆；完整配置导出另含 NeuroBook 的身份、绑定、逐条映射、变量、正文输出和参数覆盖，可在此界面再次导入。

## 设置写作映射

新导入预设自动生成映射，写手原生“职责”和“输出要求”不参与。文风、章节、人物资料和场景要求独立选择目标；多个条目映射到同一字段时按原条目顺序合并。例如将参与角色映射到 charDescription，将章节总览和具体情节都映射到预设通过 getvar 读取的同一个局部变量。

目标列表自动解析已应用的源 JSON，并随启停与生成模式更新。资料占位符以及预设定义、使用的固定名变量均可显示，局部与全局同名分开。停用、未触发或只定义未读取的字段不可选；动态变量名需要在预设中改为固定名称。删除或改名后原选择显示“目标已缺失”，需要重新选择。示例对话仍在绑定 JSON 中配置配对消息。

实际顺序是“预设变量初始化 → 本次写作资料映射 → 提示词展开”。初始化副作用只执行一次；之后展开读取初始化和映射后的变量终态。不会在提示词后追加旧写手职责或输出要求。映射覆盖本次同名初值和持久状态，下一次使用新的写作资料；回复处理仍可按既有规则更新变量。

必需条目必须真实进入消息，预览与保存会检查；未映射、条件分支未读取、正则删除或预算裁剪会明确报错。可选样文和文风禁用写法可选“不映射”。原生文件没有资料槽位、只有自定义变量时，也可以通过实际读取的变量接收资料。

已有预设保持旧绑定。点击“启用写作条目映射”才转换已知原模板内容，其余手工资料保留；转换和下拉修改均需保存后生效。绑定 JSON 的未应用草稿不会被映射操作覆盖。

每个小节还提供“直接排序／变量映射”按钮。点击“直接排序”会把该小节追加到下方提示词序列，使用左侧手柄拖动到酒馆条目之间；可展开编辑角色、正文、深度和触发条件。该小节不再同时注入映射目标。点击“变量映射”会移除对应直接条目并恢复之前选择的映射；直接模式中编辑的模板和设置仍保存在完整配置中，切回时恢复并追加到序列末尾。彻底删除直接条目会同时清除这份保存的模板。

提示词序列支持复选框、全选、单条删除和“删除所选条目”。拖动已选条目会整体移动当前序列中的选中组，并保留组内相对顺序；手柄聚焦后上下键也能调整。未加入序列的条目也可选择或删除。删除会清除源条目、所有角色顺序引用和同名资料绑定；“移出序列”仅保留条目供以后加入。修改需保存后生效，删除或停用必需写作条目会在预览和保存时被拒绝，可恢复对应条目或重新映射后保存。

## 宏、消息与预算

宏引擎默认 legacy；使用酒馆原生新宏语法的预设改选 native。两者在未开启写作映射时保留各自原生求值顺序，开启映射后使用上述三个阶段，不可随意互换。native 支持嵌套条件、惰性分支、变量简写和删除等原生语法；插件提供的宏、EJS 和 SPreset 条件脚本不执行。SPresetSettings 只保留为扩展资料，不发送给模型。

user/char 只决定宏身份，消息角色由条目和槽位决定。需要补充输入框、模型名或人物字段时，在绑定 JSON 的 nativeContext 中填写 input、model、character、names；两个引擎均使用此环境。对照日期和随机宏时可指定 now、utcOffsetMinutes、locale、randomSeed 和 chatId。实际生成冻结同次环境与消息，恢复不重新抽取随机数。浏览器显示消息 ID 等信息须显式提供；完整聊天 swipe/send_date 和插件环境不在当前文本绑定范围。

请求后处理可以沿用预设，或选择 none、merge、semi、strict、single 及文本 tools 变体。原生 JSON 的 names_behavior 支持 -1/0/1/2，分别为不加名称、默认、API name、正文名称前缀；名称默认取槽位 message.name 或对应 user/char。默认模式没有酒馆群聊/send as 环境。修改原生 JSON 后先“应用 JSON”，再预览和保存。正则查找支持不替换宏、原样替换、转义宏结果三种原生设置。

预算默认关闭，需要裁剪时勾选并选择与酒馆相同的词表（claude、cl100k_base 或 o200k_base），填写包含输出的总 token 额度后点击“应用预算”。例如输出 50000 时，总额度必须大于 50000，并且不超过作品所选模型的配置窗口。“优先保留示例”会先分配示例预算，放不下整组时仍会丢弃该组。普通条目和必需资料不能因预算而静默消失。

预览显示的“编排占用（后处理前）”不含输出额度；最终消息经过 strict 等处理后可能变长。生成时还会以同一词表复算最终提示前缀并检查模型窗口。词表与服务商实际实现是否一致需按你的酒馆设置核对，不根据模型名称自动选择。

## 图灵样本的请求设置

开发样本：`图灵预设 克5.5 布拉维坎的屠夫 写于10月10中午.json`。默认导入会绑定作品资料，无需手写 API payload。背景/补充资料只是世界书槽位文本，不会自动运行酒馆世界书激活逻辑。

- 模型在作品的写手模型设置中选择 cabo 的 `claude-opus-4-6`，接口为 OpenAI Chat Completions。
- 为对照提供的请求日志，将后处理选择为 `strict`。
- 在生成参数覆盖中输入 `{"reasoningEffort":"none"}` 并应用。原样本的 `max` 在酒馆 CUSTOM 接口会映射为 `high`，与日志的 `none` 不同。
- 保留预设其他采样参数，检查输出额度 50000 与所配置模型上限。模型额度不足时会明确失败，可调整模型配置或显式覆盖 `maxTokens`。
- 场景写作使用正常生成。酒馆的继续生成需有可续接的历史，历史消息可以在绑定中显式配置，支持多段与原生 prefill。
- 默认提取唯一完整的 `content` 标签。模型原文中的分析说明仍保存作审查证据，只将标签正文交给作品审阅和写入。

预设优先于 Profile/Provider 采样默认值，显式生成参数覆盖优先于预设；切换预设不切换服务商和模型。未知或不可保持的有效参数会明确失败。

## 状态与输出

默认 local 按项目、用途、预设和写作会话隔离；global 按项目、用途和预设延续，不跨作品。切换“仅单次尝试”可隔离两类变量。初值只在对应作用域首次创建时使用，修改初值不会覆盖已经延续的状态。

每次写手使用当次快照；审阅和恢复复用冻结消息。模型原文、存储结果、显示结果、提取正文与质检报告保存在该写手会话的输出记录中，实际请求模型与参数另有记录。回退工作流游标后仍复用同次输出，不再次求宏。不能保证网络恰好发送一次。

样本质检脚本只适配本地规则扫描，结果是供助手核对的线索。云端复核、交互补丁、聊天统计及通用脚本执行没有恢复。显示结果保留为可审查数据，不提供酒馆 DOM 插件宿主。

## 验收范围

可从场景写作、审阅退回重写和局部改写检验实际效果，核对正文不含分析说明、角色与资料不丢失、新预设只影响下一次尝试。

已实现预设提示词的两种原生宏引擎、注入与触发、名称模式、文本后处理及可选词表预算；插件数据保留并报告依赖。EJS、SPreset 插件条件与运行增强、通用扩展执行、世界书自动激活、媒体与工具、原生 Claude/Gemini 转换不在本次范围。不要将样本和文本编排通过解释为完整酒馆环境等价，模型随机文本也不保证逐字一致。
