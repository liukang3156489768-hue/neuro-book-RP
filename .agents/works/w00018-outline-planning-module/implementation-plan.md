# 大纲规划模块实施计划

## 1. 计划定位

本文是 `w00018-outline-planning-module` 的工程实施路径，不是第二份产品行为规范。长期行为以 `docs/specs/outline/` 下的 Spec 为唯一合同，产品方向和取舍以 [Proposal](../../../docs/proposals/outline-planning-module.md) 为来源。

本计划基于 2026-09-24 已确认的设计，并按 2026-09-26 的开发者决定修订：本模块只替换《新小说编写计划》中的大纲与细纲部分和伏笔部分，原始设计的三个规划 Agent 作为模块主 Agent 的子 Agent 实装，`writer.pro` 按原始设计另行新建，不提供旧文档迁移。基础设计要点：大纲库是灵感与方案库，线路规划负责正式剧情顺序；伏笔状态从正式大纲标记派生；模块 Agent 具有受限读写和审批边界；`writer.pro` 只读线路中已固定的正式内容；全屏工作台布局按项目持久化。

## 2. 交付目标

1. 管理单一总纲下的多条方案链（总纲、卷纲、章节大纲、细纲），支持跨方案共享引用和修改时写时分叉。
2. 管理伏笔条目及其埋设、强化、回收标记，动态派生四种状态，并保留来源追溯和异常提示。
3. 用节点图编排正式剧情线路，保证从左到右的顺序、主线唯一性、节点引用有效性和重复节点阻断。
4. 让 Agent 在讨论／自动模式下生成建议、执行获授权的规划操作、流式输出并留下审批、预览、撤销和审计记录。
5. 让 `writer.pro` 只读取线路规划中已固定的正式节点及其正式细纲、伏笔和素材上下文。
6. 提供全屏左右分栏工作台：Agent 区默认约占五分之一，拖拽最大不超过窗口中线，布局状态按项目恢复。

## 3. 明确非目标

- 不实现正文编辑器、正文生成器或正文 Agent 的写入能力。
- 不直接删除现有 Plot，也不在没有领域映射前另建平行 Story/Thread 真相源。
- 不以正文文本作为伏笔埋设或回收状态依据。
- 不提供从《新小说编写计划》或旧笔记导入规划的功能，也不修改该文档。
- 不把现有 `writer` Profile 改造成 `writer.pro`；本 Work 只提供规划侧的只读交接接口。
- 不承诺小屏、窄屏、移动端适配；当前桌面全屏是明确范围。
- 不在本轮选择具体模型供应商或承诺 AI 语义分析必然正确；分析失败必须阻止正式使用或退回人工处理。

## 4. 能力与规范分解

| 能力 | 行为合同 | 主要依赖 | 首期验收重点 |
|---|---|---|---|
| 大纲库与细纲 | `outline/planning-library.md` | Project 身份、结构化文件、历史、素材索引 | 层级、方案引用、写时分叉、草稿/正式、细纲偏差分析 |
| 伏笔库与标记 | `outline/foreshadowing.md` | 大纲正式内容、Markdown 解析、索引 | 四状态派生、多次埋设/回收、顺序校验、来源追溯 |
| 线路规划 | `outline/line-planning.md` | 大纲库、图文件、结构校验、分析结果 | 主线唯一、左右顺序、红黄失效、重复节点阻断 |
| 模块 Agent | `outline/agent-assistance.md` | Agent Session、审批、历史、文件操作 | 讨论/自动、批量确认、删除二次确认、撤销、流式输出；三个只读专用子 Agent 的委派 |
| 工作台 UI | `outline/workbench-ui.md` | Project UI 状态、resizable panel、三视图 | 全屏分栏、拖拽上限、布局持久化、三段切换 |
| writer.pro 交接 | `outline/writer-handoff.md` | 线路固定状态、正文 Agent 权限 | 只读正式内容，拒绝草稿/未固定/失效节点 |

## 5. 阶段与依赖

### Phase 0：领域映射与合同收敛

交付现有 Plot 的 Story/Phase/Thread/Chapter/Scene/Promise/Writer Brief 与新模块对象映射；Project Workspace 文件服务、文件历史和可重建索引的接入边界；最终字段与版本 schema、文件事务/恢复、Agent 审批/事件流/权限边界，以及与现有 Plot 的只读适配入口。结构化文件真相源、SQLite 仅索引、对象/关系删除、Markdown 标记语法已由 ADR 0022 固定，不再作为未决数据所有权问题。所有跨模块决定必须进入 ADR 或合同补充。

门禁：完成现有 API 映射、唯一 owner 核对、schema 与恢复边界确认后，才进入编码。

### Phase 1：规划存储与领域服务

交付 Project 作用域、稳定 ID、对象版本、层级/共享引用/写时分叉、伏笔来源、线路节点边类型顺序、结构化文件读写、schema 版本、快照、事务、恢复、级联影响预览和撤销记录。

依赖 Phase 0 及现有 Project/Storage/History 合同。门禁是关闭重开、并发修改、损坏文件、部分失败和回滚均可观察，且不出现第二真相源。

### Phase 2：大纲库与细纲

交付总纲、卷纲、章节大纲层级树与多方案入口；草稿/正式采用；跨方案共享引用与写时分叉；简单方向生成草案；细纲正式保存前的偏差/冲突分析；素材索引、写作指导、参考文件和篇幅要求。

门禁：正文侧只能看到线路固定的正式条目，草稿不进入 `writer.pro`。

### Phase 3：伏笔库与标记派生

交付四状态派生、UI 注释/下划线与 Markdown 标记、同章多次埋设/强化/回收、回收先于埋设和损坏标记异常、Agent 建议审批。

门禁：删除或修改有效标记后按剩余正式标记重算，正文内容不改变状态。

### Phase 4：线路规划

交付节点图与结构化文件重建；主线、支线、角色线、IF 线；从左到右顺序、连续可达、无环、重复检测和固定状态；红色删除失效、黄色修改待重分析；程序结构检查与 AI 语义冲突分析分工。

门禁：不存在可被 `writer.pro` 读取的未固定、重复、红色或黄色节点。

### Phase 5：模块 Agent

交付常驻会话、`lorebook/` 只读、规划模块读写、讨论/自动模式、删除和总纲删除审核、批量确认、撤销、审计、预览、流式输出、取消与迟到完成处理；`outline`、`Detailed outline`、`foreshadowing` 三个只读专用子 Agent 及主 Agent 的委派。

门禁：正式变更均可追溯到用户确认或有效授权，删除无自动绕过路径。

### Phase 6：全屏工作台 UI

交付全屏左右分栏、默认约五分之一 Agent 区、分隔线拖拽且左侧不超过中线、按项目保存布局、思考两段式按钮、模型列表、温度数值框/增减、讨论/自动切换、右侧三段式视图、流式上下文列表；窄屏适配明确不做。

门禁：UI 只消费领域合同，不自行派生伏笔状态、权限或线路真相。

### Phase 7：writer.pro 交接

交付规划侧只读查询：正式固定节点及正式细纲、素材索引、参考文件和本章伏笔标记处的文本（不含伏笔定义正文）；拒绝草稿、未固定、重复、红色、黄色和仅存在于大纲库的内容；规划修改不会静默覆盖正文。

门禁：读取结果可解释来源，接口无规划写入路径。`writer.pro` 本身按原始设计另行开发，端到端权限验收在其接入时完成；不改造现有 `writer`。

### Phase 8：验收和发布准备

完成合同测试、服务测试、UI 测试、项目隔离测试、损坏文件与升级中断恢复、浏览器验收。旧文档迁移已于 2026-09-26 撤销，不在范围内。

门禁：核心 Spec 均可由实现与测试证据晋升 `implemented`，发布前不保留双写路径。

## 7. 验证门禁

### 文档阶段

运行 `bun run docs:check`；人工核对 Proposal、Spec、Work、Task 的链接、状态和唯一能力归属；确认 planned Spec 没有类名、函数名、逐文件改法或未批准取舍。

### 存储与服务阶段

执行确定性合同测试、项目隔离、关闭重开、损坏文件、版本过期、并发冲突、回滚、撤销和结构化文件/SQLite 索引重建测试。

### UI 阶段

执行分隔线边界、项目偏好恢复、三段切换、流式追加、错误/取消提示的组件合同测试，并进行全屏布局、节点图、注释悬浮、审批和撤销的浏览器人工验收。

### Agent 阶段

使用 mock provider 验证讨论/自动、批量审批、删除二次确认、撤销、迟到完成和流式失败；验证不能写正文、不能写 `lorebook/`，`writer.pro` 只读正式内容。

### 发布阶段

验证规划文件失败可恢复且无双写。

## 8. 风险与决策门

| 风险/未决项 | 决策门 | 默认处理 |
|---|---|---|
| Plot 与线路规划重叠 | Phase 0 映射评审 | 本模块与 Plot 互补；完成只读适配前不编码跨模块交接 |
| 字段/schema 与文件事务未定 | Phase 0 实现合同 | 采用 ADR 0022 已固定的目录和格式，补齐字段、版本、事务与恢复语义 |
| Markdown 标记损坏/语法演进 | Phase 0 标记合同 | fail-closed，保留原文并交 Agent/用户修复 |
| AI 分析不稳定 | Phase 2/4 分析合同 | 分析失败或过期不得正式采用 |
| 工作区已有改动 | 全程 | 只修改本 Work 白名单文件，不运行 reset/clean |
