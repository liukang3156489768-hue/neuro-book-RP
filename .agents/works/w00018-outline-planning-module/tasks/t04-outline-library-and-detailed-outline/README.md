- 细纲审阅接入项目有效 Pi 模型：只读 `analyze-detail` 按章节、方案条目及 manifest 版本生成严格 JSON 报告；当前 ready generation 签发并持有报告，`adopt-detail` 独立请求绑定细纲 hash、版本、全方案上下文摘要，要求用户确认偏差、逐项处理冲突。经现有事务保存正式细纲和报告到条目 front matter 并归因 History；常规 `adopt-entry` 仍拒绝直接采用细纲。模型失败、伪造报告及关联快照过期 fail-closed；重开后草稿须重新分析，已采用的报告随规范文件恢复。本轮未调用真实模型。

## 报告作用域与提交时效

- 分析报告的上下文摘要改为仅包含所属方案的关系、标题及该方案内规范条目的版本/hash；无关方案新建、改名不再把未受影响的正式报告视为过期。共享总纲和所属方案条目变化仍改变摘要，并由领域提交入口撤回受影响的已采用细纲。
- 签发中的报告额外绑定当时 manifest revision；即使无关方案变更不影响长期报告作用域，签发后的草稿正式采用仍须通过原 revision CAS，拒绝重用旧会话报告。对应测试先 RED 后 GREEN。
