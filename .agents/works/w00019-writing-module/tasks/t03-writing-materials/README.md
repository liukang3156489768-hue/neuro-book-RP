# 写作素材的程序部分

## 目标与范围

实现 [writing.collaboration](../../../../../docs/specs/writing/collaboration.md) 中由程序填写的部分，以及四份固定结构的校验与渲染。切片 5 的写作工作流和切片 6 的改写流程直接调用这些函数。

全部是纯函数，输入是交接结果和已读好的文件内容，不读盘、不调用模型：

1. 文风文件解析：`## 文风要求` 必填且非空，`## 禁用写法` 与 `## 样文` 可为空。
2. 字数口径与上下 15% 容差。
3. 场景切分：多份细纲按方案顺序连续编号；“写作提示”小节不算场景；首个一级标题前的内容并入第一个场景；没有场景标题时报“细纲缺少场景结构”。
4. 按场景截取：细纲原文、段落写作指导、人称、目标字数；本章写作提示、本章写作指导、本章伏笔标记原文。
5. 上一章：按方案顺序找最近一个有正文的章节，截取末尾约 1500 字并按段落边界截断。
6. 摘录：按“文件路径 + 标题或段落位置”取原文，单段不超过 1000 字，每个场景合计不超过 3000 字。
7. 结构 A 到 D：助手提交的校验，结构 B 与改写提示的渲染，审阅结果的判定。

## 非目标

- 读取文件、调用模型、运行场景循环，以及 Profile 与工具权限，属于切片 5。
- 改写目标段落的扩展、上下文截取和替换，属于切片 6。
- 问题的存储与登记，属于切片 4。结构 A 不内嵌问题，问题通过问题登记单独提交。

## 验证

- 单测覆盖 Spec 验收条目中的纯函数部分：
  - 两份细纲共 4 个场景；
  - 伏笔标记原文进入每个场景，且不含定义；
  - “写作提示”小节不计为场景；
  - 细纲原文逐字一致；
  - 摘录位置不存在时被拒绝；
  - 文风文件缺少“文风要求”时报错。
- 另测：
  - 首标题前的内容；
  - 代码块中的 `#` 不算标题；
  - 目标字数的三种来源；
  - 人称的来源；
  - 上一章跨卷和无正文；
  - 摘录超限；
  - 审阅判定的字数容差与要素逐项对应。
- 应用 `typecheck` 通过；完成后在 Spec 中补“实现合同”。
