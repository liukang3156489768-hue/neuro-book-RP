# 写作问题的存储

## 目标与范围

实现 [writing.issue-feedback](../../../../../docs/specs/writing/issue-feedback.md) 的数据部分，供切片 5 的写作工作流与助手登记问题，切片 7 的界面显示徽标和列表。

1. 问题记录格式，按章保存在 `writing/issues/<章节条目 id>.yaml`，写入走项目历史。
2. 登记：
   - 登记时记录当时章节大纲与各份细纲的版本；
   - 同一章中代码与位置相同的问题只保留一条；
   - 已忽略的提示问题再次登记时仍保持已忽略；
   - 已解决的问题再次登记时重新打开。
3. 状态：存储未处理、已解决、已忽略；待复核按当前版本派生，不写入。
4. 复核：按 id 把问题标为已解决，重新登记则回到未处理并更新版本。
5. 忽略：只有提示级问题可以忽略；阻断级拒绝。
6. 查询：只列当前写作方案中的章节。某章问题文件读取失败时，只标出读取失败，不影响其他章节，也不影响概览。
7. HTTP：`GET issues` 与 `POST ignore-issue`；登记与复核只供服务端调用。

## 非目标

- 由谁、在何时登记和复核问题（写作工作流与助手的工具），属于切片 5。
- 徽标、列表与跳转界面，属于切片 7。

## 验证

- 单测：
  - 同一问题两次登记只保留一条；
  - 修改细纲后问题显示为待复核；
  - 复核后标为已解决；
  - 重新登记回到未处理；
  - 提示问题可忽略，忽略后再次登记保持已忽略；
  - 阻断问题拒绝忽略；
  - 细纲增减时显示为待复核；
  - 移出方案的章节不列出；
  - 损坏的问题文件只影响本章，且不会被覆盖。
- 服务端落盘测试与路由测试；应用 `typecheck` 通过；完成后在 Spec 中补“实现合同”。
