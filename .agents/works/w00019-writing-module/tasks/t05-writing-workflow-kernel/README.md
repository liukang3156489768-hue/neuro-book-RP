# 写作工作流内核

## 目标与范围

实现 [writing.collaboration](../../../../../docs/specs/writing/collaboration.md) 中由程序推进的整章写作部分，供 t06 的三个 Profile 与主创工具接入。

1. 运行记录：基于 `nb-workflow` 的持久 Backend，保存在 Project 内 `writing/runs/`；进程中断后按记录重放，已完成的步骤不重复执行。
2. 写作工作流（服务端 TypeScript 定义）：
   - 准备：章节可写、文风可用、场景切分；程序发现的问题登记；
   - 场景规划：助手提交结构 A，程序校验失败退回助手，主创核对（退回满 3 次停止），讨论模式再交用户确认；
   - 规划完成后复核待复核问题；
   - 场景循环：每个场景开始前复核规划版本与文风，渲染结构 B，调用写手，助手审阅结构 C，通过则追加正文，不通过最多重写 2 次；
   - 全部通过后写入正文依据，统计整章字数。
3. 任务类型：新写、续写（沿用上次运行的场景规划与已通过场景数）、整章重写。
4. 停止与续写：用户停止取消当前调用；同一章同时只能有一次运行。
5. 模型调用失败或超时重试一次。

## 非目标

- 三个 Profile 的提示词、输出 schema 与工具权限，主创的发起、停止、核对工具：t06。
- 改写流程：切片 6。
- 进度界面与运行期只读：切片 7。

## 验证

- 用 Mock 模型测试：
  - 完整写一章：正文连续、`source` 写入、运行记录含每个场景的提示和审阅；
  - 校验失败退回助手、写手未被调用；主创退回 3 次后停止；讨论模式的用户确认；
  - 审阅不通过重写，2 次后停止，正文只含此前通过的场景；
  - 写作中细纲被修改，下一场景开始时停止并登记 `PLANNING_CHANGED`；
  - 停止后续写，从第一个未通过的场景继续；
  - 进程在审阅时中断，恢复后不重复调用写手；
  - 同一章重复发起被拒绝。
- 运行记录 Backend 通过 `nb-workflow` 的一致性套件。
- 应用 `typecheck` 通过；完成后在 Spec 中补“实现合同”。
